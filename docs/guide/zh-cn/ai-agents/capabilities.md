# 智能体能做什么 {#what-agents-can-do}

通过 MCP 服务器，AI 智能体（AI agent）可以完成你在 Specivo 界面里能做的大部分操作。服务器提供约 70 个工具，名称都以 `specivo_` 开头。你很少需要直接按名称调用它们：描述你想做的事，客户端会选出合适的工具。本页按领域给这些工具分组，帮你了解能做到哪些事。连接默认只加载 `core` 工具集，除非连接 URL 要求加载更多：规划、重复任务、标签与架构管理以及 AI 支出都属于需要主动启用的[工具集](connecting.md#choose-toolsets)。

## 按领域划分的工具目录 {#the-tool-catalog-by-area}

| 领域 | 智能体能做什么 |
|---|---|
| **工作项与评论** | 列出工作项（Issue），可按与工作项列表筛选条件相同的方式缩小范围：状态、负责人（登录名、`me` 或 `none`）、标签、发布版本（版本名称或 `none`）、冲刺（Sprint）、父工作项和元数据值；读取、创建和更新工作项；编辑描述和核心字段；设置或更改工作项的[父工作项](../issues/subtasks.md)并列出其子工作项；[把工作项移动到另一个项目](../issues/updating.md#move-an-issue-to-another-project)；添加评论并读取评论历史，或读取完整的变更历史，其中会给出变更涉及的状态、人员和版本的名称。 |
| **搜索** | 使用 Specivo 的混合搜索（关键词 + 语义）搜索工作项、维基（Wiki）等内容。加上 `expand=1` 后，排名前 5 的工作项和维基页面结果还会各自列出最多 10 个与之相连的对象（链接、反向链接、关联、父级、子级、标签、版本、负责人），每个连接占一行，智能体无需再次调用就能看到结果的上下文。评论和附件不会展开。 |
| **维基** | 列出、读取、创建、编辑维基页面，向页面追加内容，包括按章节读取和编辑，以及查看历史和恢复。 |
| **元数据与架构** | 读取和设置[工作项元数据](../metadata/values.md)的值，列出可用的元数据架构。 |
| **标签** | 列出项目的[标签](../projects/tags.md)，给工作项和维基页面打标签（创建时也可以）；拥有 **管理项目** 权限时，还可以创建、重命名、改色和删除标签。 |
| **关联** | 用带类型的[关联](../issues/relations.md)（关联到、阻塞、重复于等）连接工作项，也可以移除关联。 |
| **链接** | 沿着条目之间的链接浏览：`specivo_show_issue` 和 `specivo_read_wiki` 会列出某个条目链接到哪些对象、又被哪些对象链接（反向链接），`specivo_get_links` 则以 JSON 返回它的邻域。参见[浏览链接图谱](#navigating-the-link-graph)。智能体只能看到密钥有权打开的条目之间的链接。 |
| **开发** | `specivo_issue_development(issue_ref, kinds=[...], limit, offset)` 以 JSON 返回工作项的[开发动态](../integrations/repositories.md#reading-development-activity-through-the-api-and-mcp)，文档结构与 REST API 相同：提交、拉取请求、评审、CI 运行、带环境类型的部署以及发布，并附带摘要和分页的时间线。`specivo_show_issue` 会把它汇总成一行 `Development:`。智能体只能看到密钥有权打开的工作项的开发动态。 |
| **版本** | 列出和管理版本（里程碑/发布），查看每个版本包含哪些工作项。 |
| **冲刺** | 列出冲刺，查看冲刺中的工作项，管理规划、开始、完成的整个生命周期。 |
| **重复任务** | 创建、列出、更新和删除[重复模板](../projects/recurring-tasks.md)；跳过某一次已排期的重复项；预览即将生成的重复项。模板的主题和描述支持日期宏（`{{month}}`、`{{weekday}}`……），每个重复项生成时按模板的时区展开。 |
| **工时** | 为工作项或项目记录工时并指定活动类型，或者使用自己的计时器：在某个工作项上启动、查看、停止并记录工时，或者丢弃。 |
| **AI 使用** | `specivo_log_ai_usage` 记录 AI 工具在某个工作项或项目上消耗的 token，`specivo_ai_usage` 可以列出、读取、更正、排除和重新计入 [AI 使用记录](reporting-ai-usage.md#read-correct-and-exclude-entries)。智能体自己的每条记录都会注明来自哪个智能体会话，`session_id` 可以列出某个会话在所有项目中的记录，方便智能体核对用量记到了哪里。`specivo_ai_usage_report` 按 [AI 支出报告](../projects/ai-spend-reports.md)的方式汇总支出；带上 `issue_ref` 时只统计一个工作项，`include_sub_issues=true` 会把它下面的工作项也算进来。智能体看不到自己的 token 计数，所以数字必须来自钩子、[上报器](reporting-ai-usage.md)或工具自身的 `/cost` 输出，绝不能靠估算。未指定工作项或项目时，记录会归到智能体会话正在处理的工作项（参见[智能体会话](#agent-sessions)），否则保持未分配。 |
| **AI 订阅** | `specivo_ai_subscriptions` 可以列出、添加、更正、终止和删除密钥所属用户的 [AI 订阅](../install/ai-subscriptions.md#with-your-ai-agent)，例如根据发票录入，一次调用可以录入多个套餐周期。同一套餐的周期之间出现重叠或空档时它会发出警告；限定了项目的密钥和服务账户会被拒绝。 |
| **了解环境** | `specivo_whoami`（密钥对应哪个账户）、`specivo_list_lookups`（追踪器（Tracker）/状态/优先级 ID）和 `specivo_setup_guide`（配置帮助）。 |

!!! tip "先调用了解环境的工具"
    行为规范的智能体会在创建或更新工作项之前调用 `specivo_list_lookups`，了解项目的追踪器、状态和优先级 ID，并调用 `specivo_whoami` 确认自己以谁的身份操作。接入新的智能体时，先让它运行这两个工具。

## 浏览链接图谱 {#navigating-the-link-graph}

Specivo 维护着一张图谱，记录工作项和维基页面之间的连接方式：文本链接（`ACME-42`、`[[Page]]`、指向本实例页面的链接）、关联、父级与子级、提交和拉取请求，以及条目共有的属性。标签、版本、冲刺、负责人以及部分元数据键（默认是 `component`）的值本身就是 **节点**，所以智能体可以问“这个发布版本里有什么？”，得到的是工作项本身，而不只是文本匹配结果。

`specivo_get_links` 接受一个 **ref** 作为起点：

| Ref | 起点 |
|---|---|
| `ACME-12` | 一个工作项 |
| `wiki:ACME/<slug>` | 一个维基页面 |
| `version:ACME/<name>` | 一个版本及计划纳入该版本的工作项 |
| `sprint:ACME/<name>` | 一个冲刺及其工作项 |
| `tag:ACME/<name>` | 一个标签及带有该标签的工作项和页面 |
| `component:ACME/<value>` | 一个组件（元数据 `component` 的值） |
| `metadata:ACME/<key>/<value>` | 项目列出的其他元数据键的值（见下文） |
| `user:<login>` | 一个人及指派给他的工作项 |
| `concept:ACME/<name>` | 由项目的 AI 提供商提取出的一个概念，以及提到它的内容（见下文） |

从标签、版本、冲刺、组件、元数据值或人出发时，结果会列出其成员，最新的在前，最多 `limit` 个。在其他位置，这些节点是带 `degree` 的叶子节点，`degree` 表示你可见的条目中有多少个指向它。手动填入工作项 `commits` 元数据的提交 SHA 也会成为提交节点。

可用选项：

| 选项 | 作用 |
|---|---|
| `direction` | `in`（指向这里的对象，或节点的成员）、`out` 或 `both`（默认）。 |
| `depth` | `1`（默认）或 `2`，后者会把链接到的工作项和页面再展开一层。从标签、版本、冲刺、组件、元数据值或人出发时允许 `3`，例如：一个版本、它的工作项、这些工作项的标签，以及带有这些标签的页面。 |
| `types` | 要保留的边的种类。文本链接：`wiki_link`、`mention`、`attachment_link`。类型化链接（已接受的建议）：`typed_link`。结构化：`relation`、`parent`、`child`、`attachment`、`commit`、`pull_request`。节点：`tagged`、`in_component`、`in_metadata`、`targets_version`、`in_sprint`、`assigned_to`、`mentions`（概念；写 `concept` 也可以）。建议链接：`similar`（不指名就不会返回）。指明某个节点种类后，这些节点在深度 2 时也会展开。 |
| `include_suggestions` | 设为 `true` 时，读取的种类中会加入建议链接（种类 `similar`），以及低于项目置信度阈值的概念提及。默认关闭。 |
| `limit` | 邻居数量上限，1 到 200（默认 50）。有内容被省略时，`truncated` 会指出。 |
| `to` | 另一个 ref。返回两者之间的最短路径，而不是邻居（见下文）。 |
| `filter` | 只保留符合条件的工作项，例如 `{"status": "open", "component": "importer"}`（见下文）。 |
| `format` | `json`（默认）或 `compact`。 |

附件默认不作为节点列出。每个工作项节点和页面节点改为带一个 `attachments` 计数，用 `types=["attachment"]` 可以列出附件。

**两个对象是怎么连起来的？** `specivo_get_links("ACME-12", to="wiki:ACME/runbook")` 返回最短路径，最多 4 跳，只经过密钥可见的链接。路径沿文本链接、关联和父子链接在工作项和维基页面之间逐步前进，绝不会经过密钥看不到的条目。只有当 `types` 指明了对应的种类时，路径才会穿过标签、版本等节点；不过路径的两端可以是这类节点。返回结果是一个 `path`，包含 `hops`、按顺序排列的 `nodes` 和 `edges`；或者是 `path: null` 加一个 `reason`：`no_path_within_4_hops`，或在搜索到 500 个节点后停止时的 `budget_exhausted`。`to` 不能与 `filter` 同时使用。

**筛选。** `filter` 的键有 `status`（`open`、`closed` 或状态名称）、`tracker`、`version`、`assignee`（登录名或 `me`）、`component`，以及项目元数据键列表中的其他任何键。值为列表时表示匹配其中任意一个；匹配不区分大小写；未知的键会报错。筛选在读取之后执行，此时读取最多 200 个节点，再把结果截断到 `limit`。根节点始终保留，维基页面会被丢弃，标签、版本等节点只要还连着某个被保留的工作项就会留下。

**紧凑输出。** `format="compact"` 可以节省 token。输出以一行头部开始，例如 `root: ACME-12 "Import fails" [In Progress] (14 nodes, 17 edges)`（适用时再加上 `, truncated`），之后每条边占一行：`ACME-12 -wiki_link-> wiki:ACME/runbook "Runbook"`。节点的标题只写一次，跟在它的 ref 后面。

**建议链接。** `specivo_show_issue` 和 `specivo_read_wiki` 的输出以一行 `Possibly related (suggested, not linked):` 结尾，列出同一项目中最多 5 个内容相近（附 0 到 1 的分数）且尚未被任何链接连上的工作项或页面。`specivo_get_links` 只在明确要求时才返回它们：`include_suggestions=true` 或 `types=["similar"]` 会加入种类为 `similar` 的边，带有 `suggested: true`，分数放在 `label` 中。它们是向量嵌入给出的提示，不是链接。`specivo_link_suggestion(op="accept", ref, other_ref, link_type)` 可以把某条建议变成真正的链接：两个工作项之间是一条关联（`link_type` 为关联类型，默认 `relates`）；一个工作项与一个页面之间或两个页面之间，则是一条从 `ref` 指向 `other_ref` 的类型化链接（`documents`、`implements`、`decided_in`、`supersedes` 或默认的 `see_also`），以种类 `typed_link` 列出。`op="dismiss"` 会永久隐藏这一对。两种操作都需要具备创建该链接所需的权限，也都会记入审计日志。

??? note "哪些元数据键会成为节点"
    项目管理者在 **项目设置 → 通用 → 链接图谱中的元数据键** 中选择这些键：一个逗号分隔的列表，最多 10 个[元数据](../metadata/index.md)键，默认是 `component`。这些键的每个值都会成为一个节点。把该字段留空即可关闭元数据节点。更改在下一次读取时生效，无需重建。

??? note "密钥能看到什么"
    所有内容都按密钥所属用户过滤。有权查看项目工作项或维基的人都能看到标签。版本、冲刺和元数据值需要有查看项目工作项的权限。人员节点只对已登录用户显示；`user:<login>` 只对本人、管理员，或你有权查看其工作项的项目的成员有效。

### 概念 {#concepts}

项目开启[概念提取](../projects/index.md#concept-extraction-ai)后，项目自己的 AI 提供商会列出其工作项和维基页面谈到的功能、外部系统、决策和术语。每个概念都是一个节点 `concept:ACME/<name>`（名称为小写），概念的种类作为它的 `status`。工作项或页面通过种类为 `mentions` 的边指向它提到的每个概念：`label` 是模型的置信度（例如 `0.85`），`passage` 是发现该概念的那段文本。

- `specivo_get_links("concept:ACME/billing gateway")` 列出提到该概念的工作项和页面。
- `specivo_get_links("ACME-12", types=["mentions"])` 列出一个工作项的概念。不带 `types` 时，它们和标签一样，是带 `degree` 的叶子节点。
- 低于项目置信度阈值的提及只在 `include_suggestions=true` 时返回，并标记为 `suggested: true`。
- 路径（`to=`）只有在 `types` 指明 `mentions` 时才会穿过概念。

概念是模型对文本的理解，不是谁建立的链接：依赖某个概念之前，先核对那段原文。只有当你有权查看提到某个概念的工作项或页面时，才能看到这个概念。

## 读操作与写操作 {#read-vs-write}

大约一半的工具用于 **读**（列出、显示、搜索、读取维基），另一半用于 **写**（创建工作项、添加评论、更新状态、记录工时或 AI 使用、编辑维基）。这样区分是因为权限的处理方式不同：

- **读操作** 返回密钥所属账户有权查看的全部内容。
- **写操作** *每一次* 都会按该账户的项目角色校验。账户在界面里做不了的更改，智能体通过 MCP 也做不了。

因此，[使用角色合适的专用服务账户](api-keys.md)是限定智能体权限范围的安全做法：只需要它查看的地方给只读角色，只在需要它动手的地方给可写角色。

## 每次写入都有审计 {#every-write-is-audited}

智能体发起的每一次 MCP 工具调用，无论读写，都会记录在[安全审计日志](../install/audit-log.md)中，标记为 `source=mcp`，并记下发起调用的账户、时间和来源客户端地址。管理员可以在 **管理 → 审计日志** 中查看，准确了解智能体做了什么。对工作项的编辑也会出现在普通的工作项历史和评论记录中，与人的编辑一样。智能体做的事不会被隐藏。

审计日志只覆盖 MCP。用密钥调用 REST API 的智能体会被当作普通用户对待：它对工作项和维基的编辑记在各自的历史中，不在审计日志里。

## 智能体会话 {#agent-sessions}

Specivo 还会把每个密钥的调用归入 **智能体会话**。每个 MCP 连接都有自己的会话：客户端连接时（例如新开一个 Claude Code 会话）会开始一个不带工作项的新会话，即使另一个客户端正在同时使用同一个密钥，或者一分钟前才停止。客户端在网络中断或服务器重启后带着会话 id 重新连接时，会沿用原来的会话。同一密钥的普通 REST 调用共用一个单独的会话。同一连接上间隔不到 30 分钟（`AGENT_SESSION_TIMEOUT`，单位为秒）的调用属于同一个会话；停顿更久之后会开始新的会话。会话会记录：

- 发起调用的 **客户端**：取它连接时声明的名称和版本（例如 `claude-code` 和 `2.1.0`），没有的话取其 `User-Agent` 请求头中的第一个产品名；
- **智能体正在处理的工作项**：通过 MCP 时，取智能体最近一次执行以下任一操作的工作项：创建时状态为 *进行中*（活跃状态组中的任一状态）或指派给了自己的账户；把它改为这类状态；把它指派给自己的账户；在它处于进行中且已指派给自己的账户时更新它（这样智能体继续处理自己的工作项时会再次标记它，即使没有任何改动）；在它上面启动计时器。以最近的一次为准。只会记录密钥所属账户可见的工作项。
- **会话的打开方式**：`mcp`（MCP 连接）或 `rest`（普通 REST 调用）；
- **客户端自己的会话 id 及其父会话的 id**，前提是客户端上报了它们（见下文）。

自带会话 id 的智能体客户端（例如 Hermes 会话）可以用 `specivo_agent_session(op="set", external_session_id=..., parent_session_id=...)` 上报这些 id，并可以在同一次调用中用 `issue_ref` 指明正在处理的工作项。id 长度为 1 到 200 个字符，可包含字母、数字和 `. _ : -`。这次调用只修改发起它的那个连接的会话，父会话也只会关联到同一账户的会话，所以其他账户的 id 绝不会挂到你的会话上。之后[上报器](reporting-ai-usage.md)用相同的 `session_id` 发送用量时，Specivo 会把用量归到该会话的工作项（如果该会话没有指明工作项，则归到其父会话链中最近的一个），而不是根据工作时间去猜。`specivo_agent_session(op="get")` 显示当前会话。设置 id 的操作会记入审计日志。

在一个 MCP 连接上运行多个对话的客户端（例如 Hermes 的子智能体或网关对话），要在每个对话开始工作前调用 `specivo_agent_session(op="set", external_session_id=...)`。Specivo 会在该连接上选中这个 id 对应的会话，没有则创建，连接之后的调用都计入它；带 `external_session_id` 的 `op="get"` 显示那个会话。同一连接上同时运行的工具调用会计入最后选中的会话，所以如果这一点很重要，就给这样的会话各开一个连接。`specivo_agent_session(op="set", issue_ref="")` 会清除会话正在处理的工作项；这一更改会被审计。

客户端的一个对话就是一个会话，无论它的调用以什么方式到达：

- 带有相同客户端会话 id 的 [Hermes 事件](hermes-events.md)会并入该账户已打开的会话。一次运行结束时，只会结束由这些事件打开的会话，不会结束对话仍在其中进行的 MCP 会话。
- 带有请求头 `X-Agent-Session-Id: <id>` 的 REST 调用会并入具有该 id 的已打开会话，或者开始一个带有该 id 的 REST 会话。不带这个请求头的 REST 调用绝不会并入这样的会话。
- 带有请求头 `X-Agent-Background: 1` 的 REST 调用属于客户端自身的例行维护，例如轮询新工作项的同步。它不会打开或延长任何会话，因此不会让会话一直显得活跃。它照常经过身份验证和审计。

### 代理会话页面 {#the-agent-sessions-page}

每个项目的侧边栏中都有一个 **代理会话** 页面。它列出项目成员账户的会话，最近活跃的在前：**账户**（智能体账户带有 **服务账户** 徽标）、**客户端**、**类型**（MCP 或 REST）、会话正在处理的 **工作项**、**开始于** 的时间、**最近活动**（带有 **活跃**、**未启用** 或 **已结束** 标记）、**工具调用** 的次数，以及与它关联的 **AI 使用**（你有权查看的记录和支出）。可以按 **账户**（登录名）、**工作项**（编号，例如 `ACME-12`）和 **显示**（全部、仅活跃、仅不活跃）筛选。如果会话正在处理的工作项你无权查看，该会话不会列出。

项目管理者（拥有 **管理项目** 权限的任何人，以及管理员）可以打开会话。会话页面显示账户和客户端、客户端的会话 id 及其 **父会话**、开始时间、最近活跃时间和结束时间、父会话链中的 **相关会话**，以及它的 **工具调用**：它运行过的 MCP 工具，最新的在前，每页 20 条，附带事件以及每次调用指明的对象（项目标识、工作项编号、页面 slug）。这些数据来自安全审计日志，所以只显示这些元数据，绝不显示发送给工具的内容或工具返回的内容。会话在其他项目中发起的调用不会显示，在项目内工作的工具发起的不带项目的调用也不会显示；`specivo_whoami`、`specivo_list_projects` 和 `specivo_list_lookups` 的调用会显示。**父会话** 和 **相关会话** 只显示你可以在本页面打开的会话。它们下方是与该会话关联的 AI 使用（最新的 20 条记录）：用它的客户端会话 id 上报的记录；如果它没有客户端会话 id，则是同一账户中开始和结束时间都落在会话时间范围内的记录。打开会话的操作会记入审计日志。

某个区域的条目超过 20 条时，其上方会出现 **较新** 和 **较旧** 链接以及每页条数选项（20、50 或 100），并在原位加载该区域，不会重新加载页面。没有 JavaScript 时，这些链接会重新加载页面。**工具调用** 和 **AI 使用** 各自独立分页。

这个页面出现之前发起的工具调用没有关联到会话，所以较早的会话不显示任何工具调用。

REST API 中也有同样的数据：`GET /api/v1/projects/{key}/agent-sessions/` 返回分页列表（`offset`、`limit`，以及筛选条件 `account`、`issue`、`active` 和 `external_session_id`）；对项目管理者，`GET .../agent-sessions/{id}/` 返回单个会话，带有 `tool_call_count` 和 `usage_entry_count`，`GET .../agent-sessions/{id}/events/` 返回它的工具调用。

### 工作项上的智能体标签页 {#the-agents-tab-on-an-issue}

工作项的 **智能体** 标签页显示智能体为它做了什么、花了多少钱：每个处理过该工作项的智能体会话占一个区块，最新的在前，每页 20 个。它回答的是“我的智能体昨晚做了什么，花了多少钱”。与会话页面一样，这个标签页只对项目管理者（拥有 **管理项目** 权限的任何人，以及管理员）开放，并且只出现在他们能看到的工作项上。

如果会话处理过某个工作项，或者为该工作项上报的 AI 使用带有它的客户端会话 id，这个会话就属于该工作项。每个区块从会话父会话链的顶端开始：它上方的会话和它的子智能体都在同一个区块中，子智能体列在它下面。如果同一次运行在 Specivo 中有两份记录，一份是 MCP 连接，一份是带有相同客户端会话 id 的 [Hermes 事件](hermes-events.md)，两者会显示为一个会话。有子工作项的工作项会有一个 **包含子问题** / **仅此问题** 开关；位于你无权查看的子工作项上的会话不会显示。

每个区块显示：

- **账户**（带 **服务账户** 徽标）、客户端、类型（MCP、REST、Webhook）、智能体配置（如果它的用量指明了配置），以及表示运行时无人看管的 **无人值守** 标记；
- **状态**：**运行中**（最近 30 分钟内活跃）、**已完成**、**已中断**（Hermes 报告运行被中断）或 **空闲**，以及开始时间、结束时间或最近活跃时间，还有耗时；
- **计数**：工具调用、请求的审批及其答复情况，以及子智能体；
- 区块的 **AI 费用**：为其中会话上报的用量的支出和 API 等价价值、token 数和记录条数，以项目的报告货币计，不含席位费用。这一行遵循 [AI 使用](../projects/ai-usage.md)的规则：你需要有 **查看 AI 使用** 权限，并且只能看到你的角色允许读取的记录。在上报器发送用量之前（每 30 分钟一次），这一行显示 **尚未上报**；
- 子智能体，每个都带有状态和指向其自身页面的链接；
- **步骤**：会话及其子智能体最新的 30 条工具调用、审批以及子智能体的启动和停止，与会话页面上的一样。**全部显示** 和 **打开会话** 会跳转到该页面。

与会话页面一样，这个标签页只显示元数据（工具名称、状态、调用指明的编号或标识），绝不显示发送给工具的内容或工具返回的内容，也不显示这些会话在其他项目中做的事。打开这个标签页会从你的额度中消耗一次 AI 报告，与 **AI 使用** 标签页相同。这个标签页也可以作为独立页面访问：`/issue/{key}/agents/`。

REST API 提供同样的列表：`GET /api/v1/issues/{key}/agent-sessions/` 返回分页列表（`offset`、最大为 50 的 `limit`、用于包含子工作项的 `sub=true`），其中有每个会话的 id、账户、客户端、状态、计数、子智能体 id，对有权查看 AI 使用的读者还有 `cost`。

会话的工作项只是把 AI 使用归到某个工作项的提示（不带工作项或项目的 `specivo_log_ai_usage` 会使用它，前提是账户有权在那里记录用量），它不授予任何权限。提示词和对话内容一概不会存储。

## 文件上传通过 REST API 完成 {#file-uploads-go-through-the-rest-api}

MCP 工具 **只处理文本**：它们可以读写工作项、评论和维基文本，但不能上传二进制文件。要添加附件，请用 `curl` 调用 Specivo 的 REST API，使用同一个 `spv_…` 密钥：

```bash
curl -X POST https://your-specivo-host/api/v1/attachments/ \
  -H "Authorization: Bearer spv_your_api_key_here" \
  -F "file=@./diagram.png" \
  -F "container_type=Issue" \
  -F "container_id=123"
```

`container_type` 为 `Issue`、`WikiPage` 或 `Journal`（评论），`container_id` 是它的数字 id。添加文件需要有权修改文件所附加到的对象：

| 附加到 | 所需权限 |
|---|---|
| 工作项 | **编辑工作项** 或 **添加评论**；或者在该账户创建的工作项上拥有 **创建工作项** |
| 维基页面 | **管理维基页面** |
| 评论 | **编辑任意评论**，或者在该账户自己的评论上拥有 **编辑自己的评论** |

工作项上的文件会记录在工作项的历史中（“已添加文件 diagram.png”）。要把它和所属的那次编辑或评论记在一起，请加上 `-F "journal_id=…"`：值为 `PATCH /api/v1/issues/{ref}/` 返回的 `journal_id`（编辑没有改动任何内容时为 null），或 `POST /api/v1/issues/{ref}/journals/` 返回的评论 `id`。每次上传的响应中也带有 `journal_id`，同一批的后续文件可以并入同一条记录。

!!! note "REST API 基础"
    REST 身份验证 **只** 使用 `Authorization: Bearer spv_…` 请求头，每个 API URL 都需要以 **斜杠结尾**。连接 MCP 客户端用的那个密钥在这里同样可用。
