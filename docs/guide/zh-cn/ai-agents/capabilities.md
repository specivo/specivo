# 智能体能做什么 {#what-agents-can-do}

通过 MCP 服务器，AI 智能体（AI agent）能完成你在 Specivo 界面里的大多数操作。服务器提供约 40 个工具，名称都以 `specivo_` 开头。你很少需要按名称直接调用它们：只要描述想做的事，客户端就会选用合适的工具。本页按领域对这些工具分组，方便你了解它们大致能做些什么。

## 按领域划分的工具目录 {#the-tool-catalog-by-area}

| 领域 | 智能体能做什么 |
|---|---|
| **工作项与评论** | 列出、查看、创建和更新工作项（Issue）；编辑描述和核心字段；设置或更改工作项的[父工作项](../issues/subtasks.md)并列出其子工作项；[把工作项移到另一个项目](../issues/updating.md#move-an-issue-to-another-project)；添加评论、读取评论历史，或读取完整的变更历史（包括每次变更涉及的状态、人员和版本名称）。 |
| **搜索** | 使用 Specivo 的混合搜索（关键词 + 语义）在工作项、维基（Wiki）等内容中搜索。 |
| **维基** | 列出、读取、创建、编辑维基页面，或在页面末尾追加内容；支持按章节读取和编辑，以及查看历史记录和恢复。 |
| **元数据与架构** | 读取和设置[工作项元数据](../metadata/values.md)的值，并列出可用的元数据架构。 |
| **标签** | 列出项目的[标签](../projects/tags.md)，为工作项和维基页面添加标签（也可在创建时直接添加）；拥有 **管理项目** 权限时，还能创建、重命名、改色和删除标签。 |
| **关联** | 用带类型的[关联](../issues/relations.md)把工作项连接起来（关联到、阻塞、重复于等），也可以移除关联。 |
| **版本** | 列出并管理版本（里程碑/发布），查看每个版本包含哪些工作项。 |
| **冲刺** | 列出冲刺（Sprint），查看冲刺中的工作项，并管理规划、开始、完成的整个生命周期。 |
| **重复任务** | 创建、列出、更新和删除[重复任务模板](../projects/recurring-tasks.md)；跳过某一次计划中的重复项；预览即将到来的重复项。模板的主题和描述支持日期宏（`{{month}}`、`{{weekday}}` 等），会按模板所在时区在每个重复项中展开。 |
| **时间** | 为工作项或项目记录工时并指定活动类型；也可以使用自己的计时器：在某个工作项上启动、查看、停止并记录工时，或者直接丢弃。 |
| **基础信息** | `specivo_whoami`（当前密钥对应哪个账户）、`specivo_list_lookups`（追踪器/状态/优先级 ID）和 `specivo_setup_guide`（配置帮助）。 |

!!! tip "先调用基础信息工具"
    行为良好的智能体会先调用 `specivo_list_lookups` 了解项目的追踪器（Tracker）、状态和优先级 ID，再去创建或更新工作项；还会调用 `specivo_whoami` 确认自己以哪个账户在操作。接入新的智能体时，先让它运行这两个工具。

## 读操作与写操作 {#read-vs-write}

大约一半工具是**读**操作（列出、查看、搜索、读取维基），另一半是**写**操作（创建工作项、添加评论、更新状态、记录工时、编辑维基）。这个区分之所以重要，是因为权限：

- **读操作** 返回密钥所属账户有权看到的所有内容。
- **写操作** *每次*都会按该账户在项目中的角色校验。账户在界面里做不了的修改，智能体通过 MCP 同样做不了。

正因如此，[为智能体使用专门的服务账户并分配合适的角色](api-keys.md)才是划定其权限范围的安全做法：只需要查看的地方给只读角色，只有需要操作的地方才给写权限角色。

## 每次写操作都有审计记录 {#every-write-is-audited}

智能体的每次写操作都会记录到**安全审计日志**中，标记为 `source=mcp`，并附带操作账户和时间。项目管理者可以查看这份日志，准确了解智能体改了什么。工作项的修改也会和人工修改一样出现在正常的工作项历史和评论记录中，智能体做的任何事都不会被隐藏。

## 文件上传走 REST API {#file-uploads-go-through-the-rest-api}

MCP 工具**只处理文本**：可以读写工作项、评论和维基文本，但不能上传二进制文件。要添加附件，请用 `curl` 调用 Specivo 的 REST API，并复用同一个 `spv_…` 密钥：

```bash
curl -X POST https://your-specivo-host/api/v1/attachments/ \
  -H "Authorization: Bearer spv_your_api_key_here" \
  -F "file=@./diagram.png" \
  -F "container_type=Issue" \
  -F "container_id=123"
```

`container_type` 取值为 `Issue`、`WikiPage` 或 `Journal`（即评论），`container_id` 是对应对象的数字 id。添加文件需要拥有修改附件所属对象的权限：

| 附件所属对象 | 所需权限 |
|---|---|
| 工作项 | **编辑工作项** 或 **添加评论**；对于该账户自己创建的工作项，**创建工作项** 也可以 |
| 维基页面 | **管理维基页面** |
| 评论 | **编辑任意评论**；对于该账户自己的评论，**编辑自己的评论** 也可以 |

添加到工作项的文件会记入该工作项的历史记录（“已添加文件 diagram.png”）。若要把它和所属的编辑或评论记在同一条目中，加上 `-F "journal_id=…"`：`journal_id` 可以是 `PATCH /api/v1/issues/{ref}/` 返回的 `journal_id`（如果该编辑没有改动任何内容则为 null），也可以是 `POST /api/v1/issues/{ref}/journals/` 返回的评论 `id`。每次上传的响应也会带上 `journal_id`，同一批次的其他文件可以借此归入同一条目。

!!! note "REST API 基础"
    REST 认证**只**通过 `Authorization: Bearer spv_…` 请求头完成，而且每个 API URL 都必须带**末尾斜杠**。连接 MCP 客户端用的那把密钥在这里同样可用。
