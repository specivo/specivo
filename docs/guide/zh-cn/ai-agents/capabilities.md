# 智能体能做什么 {#what-agents-can-do}

通过 MCP 服务器，AI 智能体（AI agent）可以完成你在 Specivo 界面里能做的大部分操作。服务器提供约 40 个工具，名称都以 `specivo_` 开头。你很少需要按名称调用它们：描述你想做的事，客户端会自己选对工具。本页按领域把这些工具分组，帮你了解智能体的能力范围。

## 按领域划分的工具目录 {#the-tool-catalog-by-area}

| 领域 | 智能体能做什么 |
|---|---|
| **工作项与评论** | 列出工作项（Issue），可像工作项列表的筛选条件那样缩小范围（状态、负责人（登录名、`me` 或 `none`）、标签、发布版本（版本名称或 `none`）、冲刺（Sprint）、父工作项和元数据值）；读取、创建和更新工作项；编辑描述和核心字段；设置或更改工作项的[父工作项](../issues/subtasks.md)并列出其子工作项；[把工作项移到另一个项目](../issues/updating.md#move-an-issue-to-another-project)；添加评论，读取评论历史，或读取完整的变更历史，其中会给出每次变更涉及的状态、人员和版本的名称。 |
| **搜索** | 使用 Specivo 的混合搜索（关键词 + 语义）搜索工作项、维基（Wiki）等内容。加上 `expand=1` 后，排名前 5 的工作项和维基页面结果还会各自列出最多 10 个与之相连的对象（链接、反向链接、关联、父项、子项、标签、版本、负责人），每个连接占一行，智能体不必再调用一次就能看到结果的上下文。评论和附件不会展开。 |
| **维基** | 列出、读取、创建、编辑维基页面，向页面追加内容，支持按章节读取和编辑，以及查看历史和恢复。 |
| **元数据与架构** | 读取和设置[工作项元数据](../metadata/values.md)的值，列出可用的元数据架构。 |
| **标签** | 列出项目的[标签](../projects/tags.md)，给工作项和维基页面打标签（创建时也可以）；拥有 **管理项目** 权限时，还能创建、重命名、改色和删除标签。 |
| **关联** | 用带类型的[关联](../issues/relations.md)（关联到、阻塞、重复于等）连接工作项，也可以移除关联。 |
| **链接** | 沿着对象之间的链接跳转：`specivo_show_issue` 和 `specivo_read_wiki` 会列出一个对象链接到什么、什么链接到它（反向链接），`specivo_get_links` 则以 JSON 返回它的邻域。参见[在链接图中导航](#navigating-the-link-graph)。智能体只能看到密钥有权打开的对象之间的链接。 |
| **开发** | `specivo_issue_development(issue_ref, kinds=[...], limit, offset)` 以 JSON 返回工作项的[开发动态](../integrations/repositories.md#reading-development-activity-through-the-api-and-mcp)，与 REST API 返回的文档相同：提交、拉取请求、评审、CI 运行、部署（含环境类型）和发布，并附带摘要和分页的时间线。`specivo_show_issue` 会把它汇总成一行 `Development:`。智能体只能看到密钥有权打开的工作项的开发动态。 |
| **版本** | 列出和管理版本（里程碑/发布），查看每个版本包含哪些工作项。 |
| **冲刺** | 列出冲刺，查看冲刺中的工作项，管理计划、开始、完成的整个生命周期。 |
| **重复任务** | 创建、列出、更新和删除[重复模板](../projects/recurring-tasks.md)；跳过某一次已排期的重复项；预览即将生成的重复项。模板的主题和描述支持日期宏（`{{month}}`、`{{weekday}}` 等），每个重复项生成时按模板的时区展开。 |
| **时间** | 为工作项或项目记录工时并指定活动类型，或者使用自己的计时器：在某个工作项上启动、查看、停止并记录工时，或者丢弃。 |
| **AI 使用** | `specivo_log_ai_usage` 记录某个 AI 工具在工作项或项目上消耗的 token，`specivo_ai_usage` 可以列出、读取、更正、排除和重新计入 [AI 使用记录](reporting-ai-usage.md#read-correct-and-exclude-entries)。智能体自己的每条记录都标明来自哪个智能体会话，用 `session_id` 可以列出一个会话在所有项目中的记录，方便智能体核对用量记到了哪里。`specivo_ai_usage_report` 汇总支出，与 [AI 支出报告](../projects/ai-spend-reports.md)一致；加上 `issue_ref` 时只统计一个工作项，`include_sub_issues=true` 会把它下面的工作项也算进来。智能体看不到自己的 token 计数，因此数字必须来自钩子、[上报工具](reporting-ai-usage.md)或工具自身的 `/cost` 输出，绝不能靠估算。如果没有指定工作项或项目，记录会归到智能体会话正在处理的工作项（参见[智能体会话](#agent-sessions)），否则保持未分配。 |
| **AI 订阅** | `specivo_ai_subscriptions` 可以列出、添加、更正、终止和删除密钥所属用户的 [AI 订阅](../install/ai-subscriptions.md#with-your-ai-agent)，例如根据账单录入，一次调用可以录入多个套餐周期。同一套餐的周期之间有重叠或空档时它会给出警告；限定了项目的密钥和服务账户不能使用它。 |
| **熟悉环境** | `specivo_whoami`（密钥对应哪个账户）、`specivo_list_lookups`（追踪器（Tracker）、状态、优先级的 ID）和 `specivo_setup_guide`（配置帮助）。 |

!!! tip "先调用熟悉环境的工具"
    行为规范的智能体会在创建或更新工作项之前调用 `specivo_list_lookups`，了解项目的追踪器、状态和优先级 ID，并调用 `specivo_whoami` 确认自己以谁的身份操作。接入新的智能体时，让它先运行这两个工具。

## 在链接图中导航 {#navigating-the-link-graph}

Specivo 维护着一张图，记录工作项和维基页面之间的连接：文本链接（`ACME-42`、`[[Page]]`、指向本实例页面的链接）、关联、父项和子项、提交和拉取请求，以及对象之间共有的东西。标签、版本、冲刺、负责人和某些元数据键（默认是 `component`）的值本身就是 **节点**，所以智能体可以问“这个版本里有什么？”，拿到的是工作项，而不只是文本匹配。

`specivo_get_links` 需要一个 **引用**（ref）作为起点：

| 引用 | 起点 |
|---|---|
| `ACME-12` | 一个工作项 |
| `wiki:ACME/<slug>` | 一个维基页面 |
| `version:ACME/<name>` | 一个版本及计划在该版本完成的工作项 |
| `sprint:ACME/<name>` | 一个冲刺及其中的工作项 |
| `tag:ACME/<name>` | 一个标签及带有该标签的工作项和页面 |
| `component:ACME/<value>` | 一个组件（元数据 `component` 的值） |
| `metadata:ACME/<key>/<value>` | 项目列出的其他元数据键的值（见下文） |
| `user:<login>` | 一个人及指派给他的工作项 |

从标签、版本、冲刺、组件、元数据值或人出发时，结果会列出其成员，最新的在前，最多 `limit` 个。在其他位置，这些节点是叶子节点，带有 `degree`，即你有权查看且指向它们的对象数量。在工作项的 `commits` 元数据中手工填写的提交 SHA 也会成为提交节点。

可用选项：

| 选项 | 作用 |
|---|---|
| `direction` | `in`（什么指向这里，或节点的成员）、`out` 或 `both`（默认）。 |
| `depth` | `1`（默认）或 `2`，后者会把链接到的工作项和页面再展开一层。从标签、版本、冲刺、组件、元数据值或人出发时可以用 `3`，例如：一个版本、它的工作项、这些工作项的标签，以及带有这些标签的页面。 |
| `types` | 要保留的边类型。文本链接：`wiki_link`、`mention`、`attachment_link`。结构化：`relation`、`parent`、`child`、`attachment`、`commit`、`pull_request`。节点：`tagged`、`in_component`、`in_metadata`、`targets_version`、`in_sprint`、`assigned_to`。指定某种节点类型后，这些节点在深度 2 时也会展开。 |
| `limit` | 最多返回的邻居数，1 到 200（默认 50）。有邻居未返回时 `truncated` 会标明。 |
| `to` | 另一个引用。返回两者之间的最短路径，而不是邻居（见下文）。 |
| `filter` | 只保留符合条件的工作项，例如 `{"status": "open", "component": "importer"}`（见下文）。 |
| `format` | `json`（默认）或 `compact`。 |

附件默认不作为节点列出。每个工作项和页面节点改为带一个 `attachments` 计数，用 `types=["attachment"]` 可以列出附件。

**两个对象如何相连**？`specivo_get_links("ACME-12", to="wiki:ACME/runbook")` 返回最短路径，最多 4 跳，只经过密钥有权查看的链接。路径沿文本链接、关联和父子链接在工作项和维基页面之间逐步前进，绝不会经过密钥无权查看的对象。标签、版本等其他节点只有在 `types` 指定了它们的类型时才会被经过，但路径的两端都可以是这类节点。返回结果是一个 `path`，包含 `hops`、按顺序排列的 `nodes` 和 `edges`；或者是 `path: null` 加一个 `reason`：`no_path_within_4_hops`，或搜索在 500 个节点后停止时的 `budget_exhausted`。`to` 不能与 `filter` 同时使用。

**筛选**。`filter` 的键有 `status`（`open`、`closed` 或状态名称）、`tracker`、`version`、`assignee`（登录名或 `me`）、`component`，以及项目元数据键列表中的其他任何键。值为列表时表示匹配其中任意一个；匹配不区分大小写；未知的键会报错。筛选在读取之后执行，此时读取最多 200 个节点，再把结果裁剪到 `limit`。根节点始终保留，维基页面会被去掉，标签、版本等其他节点只要还连着某个保留下来的工作项就会留下。

**紧凑输出**。`format="compact"` 可以节省 token。输出以一行头部开始，例如 `root: ACME-12 "Import fails" [In Progress] (14 nodes, 17 edges)`（有截断时再加上 `, truncated`），然后每条边一行：`ACME-12 -wiki_link-> wiki:ACME/runbook "Runbook"`。节点的标题只写一次，跟在它的引用后面。

??? note "哪些元数据键会成为节点"
    项目管理者在 **项目设置 → 常规 → 链接图中的元数据键** 中选择这些键：一个以逗号分隔的列表，最多 10 个[元数据](../metadata/index.md)键，默认是 `component`。这些键的每个值都会成为一个节点。把该字段留空即可关闭元数据节点。更改在下一次读取时生效，无需重建。

??? note "密钥能看到什么"
    所有内容都按密钥所属用户的权限过滤。有权查看项目工作项或维基的人都能看到标签。版本、冲刺和元数据值需要查看项目工作项的权限。人员节点只对已登录用户显示，`user:<login>` 只能用于你自己，或者在你是管理员、或你与对方同属某个你能查看其工作项的项目时使用。

## 读与写 {#read-vs-write}

大约一半的工具负责 **读**（列出、查看、搜索、读取维基），另一半负责 **写**（创建工作项、添加评论、更新状态、记录工时或 AI 使用、编辑维基）。这样区分是因为权限处理不同：

- **读操作** 返回密钥所属账户有权查看的全部内容。
- **写操作** *每次* 都会按该账户的项目角色检查。账户在界面里做不了的更改，智能体通过 MCP 也做不了。

因此，要限定智能体的权限范围，安全的做法是使用[角色配置得当的专用服务账户](api-keys.md)：只需要查看的地方给只读角色，只有需要操作的地方才给可写角色。

## 每次写入都有审计记录 {#every-write-is-audited}

智能体发起的每一次 MCP 工具调用，无论读还是写，都会记入[安全审计日志](../install/audit-log.md)，标记为 `source=mcp`，并记下发起调用的账户、时间和来源客户端地址。管理员可以在 **管理 → 审计日志** 中查看，准确了解智能体做了什么。对工作项的编辑还会出现在普通的工作项历史和评论记录中，与人的编辑一样。智能体做的任何事都不会被隐藏。

审计日志只覆盖 MCP。智能体用自己的密钥调用 REST API 时，会被当作普通用户对待：它对工作项和维基的编辑记在各自的历史里，不在审计日志中。

## 智能体会话 {#agent-sessions}

Specivo 还会把每个密钥的调用归入 **智能体会话**。每个 MCP 连接都有自己的会话：客户端连接时（例如新开一个 Claude Code 会话），会开始一个不带工作项的新会话，即使另一个客户端正在同时使用同一个密钥，或者一分钟前刚停止。客户端在网络中断或服务器重启后带着会话 ID 重新连接时，会保留原来的会话。同一密钥的普通 REST 调用共用一个单独的会话。同一连接中间隔不到 30 分钟（`AGENT_SESSION_TIMEOUT`，单位为秒）的调用属于同一个会话；停顿更久之后会开始新会话。会话记录以下内容：

- **客户端**：发起调用的客户端，取它连接时声明的名称和版本（例如 `claude-code` 和 `2.1.0`），没有声明时取其 `User-Agent` 请求头中的第一个产品名；
- **智能体正在处理的工作项**：智能体通过 MCP 最近一次执行了以下任一操作的工作项：创建时即处于*进行中*状态（活动组中的任意状态）或已指派给自己的账户；把它改为这类状态；把它指派给自己的账户；在它处于进行中且已指派给自己的账户时更新它（这样智能体继续处理自己的工作项时会再次标记它，即使没有任何改动）；或在它上面启动计时器。以最近的一次为准。只有密钥所属账户能看到的工作项才会被记录。

会话的工作项只是把 AI 使用归到某个工作项的一个提示（`specivo_log_ai_usage` 未指定工作项或项目时会使用它，前提是该账户有权在那里记录使用量）；它不授予任何权限。提示词和对话内容一概不会存储。

## 文件上传走 REST API {#file-uploads-go-through-the-rest-api}

MCP 工具 **只处理文本**：它们可以读写工作项、评论和维基文本，但不能上传二进制文件。要添加附件，用 `curl` 调用 Specivo 的 REST API，使用同一个 `spv_…` 密钥：

```bash
curl -X POST https://your-specivo-host/api/v1/attachments/ \
  -H "Authorization: Bearer spv_your_api_key_here" \
  -F "file=@./diagram.png" \
  -F "container_type=Issue" \
  -F "container_id=123"
```

`container_type` 可以是 `Issue`、`WikiPage` 或 `Journal`（评论），`container_id` 是它的数字 ID。添加文件需要有权修改文件所附加到的对象：

| 附加到 | 所需权限 |
|---|---|
| 工作项 | **编辑工作项** 或 **添加评论**；或者在该账户创建的工作项上拥有 **创建工作项** |
| 维基页面 | **管理维基页面** |
| 评论 | **编辑任意评论**，或者在该账户自己的评论上拥有 **编辑自己的评论** |

工作项上的文件会记入工作项的历史（“已添加文件 diagram.png”）。如果要把它和所属的编辑或评论记在一起，加上 `-F "journal_id=…"`：取 `PATCH /api/v1/issues/{ref}/` 返回的 `journal_id`（编辑没有改动任何内容时为 null），或 `POST /api/v1/issues/{ref}/journals/` 返回的评论 `id`。每次上传的响应中也带有 `journal_id`，同一批的后续文件可以借此归入同一条记录。

!!! note "REST API 基础"
    REST 认证 **只** 使用 `Authorization: Bearer spv_…` 请求头，并且每个 API URL 都必须 **以斜杠结尾**。连接 MCP 客户端的那个密钥在这里同样可用。
