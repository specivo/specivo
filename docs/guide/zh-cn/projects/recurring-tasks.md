# 重复任务 {#recurring-tasks}

**重复任务模板**是一种按排期自动生成工作项（Issue）的模板。你不必再记着每周或每月手动创建同一个工作项：只需定义一次模板，Specivo 会自动为你创建每一个实例。

重复任务位于左侧边栏的 **项目 → （你的项目） → 重复任务**。

<!-- screenshot: recurring pattern list page -->

## 什么是重复模板 {#what-a-pattern-is}

重复模板本身不是工作项，它包含两部分内容：

1. **排期**：何时触发、多久触发一次（每天、每周、每月、每年，以及各种细化规则）。
2. **工作项模板**：每个生成的工作项在创建时自带的字段，包括主题、追踪器、状态、优先级、负责人、描述和元数据。

排期每触发一次，Specivo 就按模板在项目中创建一个真实的工作项。这个工作项与手动创建的完全一样：可以评论、流转状态、记录工时，也可以与其他工作项建立关联。

## 创建重复模板 {#creating-a-pattern}

进入项目的 **重复任务** 区域，点击 **新建重复模板**。

<!-- screenshot: recurring pattern form -->

### 名称与启用开关 {#name-and-enabled-toggle}

给模板起一个在列表里一眼就能认出的名字，例如“每周状态报告”或“每月数据库备份检查”。**已启用** 开关决定模板是否实际生成工作项。想暂停一段时间时，停用即可，不必删除。

### 排期 {#schedule}

排期区域用来定义重复规则。

| 字段 | 作用 |
|---|---|
| **频率** | 多久一次：**每天**、**每周**、**每月** 或 **每年** |
| **重复间隔** | 间隔数，频率为每周时填 `2` 表示每两周一次 |
| **按星期** | 在星期几触发（用于每周规则，或与设置位置组合用于每月规则） |
| **按月内日期** | 具体日期数字（`1`、`15`，`-1` 表示当月最后一天），仅每月规则可用 |
| **设置位置** | 周期内的第 n 次（`1` = 第一个，`2` = 第二个，`-1` = 最后一个），与星期组合可表达“第二个星期二” |
| **开始** | 整个序列锚定的日期和时间（第一个可能的重复项） |
| **时区** | 计算重复项所用的 IANA 时区，例如 `Europe/London`。重复项全年都在同一钟表时间触发，自动适应夏令时。 |

!!! tip "实时预览"
    编辑规则时，表单会显示 **后续重复项** 预览，你可以在保存前确认排期是否正确。

#### 示例 {#examples}

- **每周一**：频率选每周，不选星期（将以开始日期所在的星期几为锚点，所以开始日期要设成周一），或直接选 MO。
- **每两周的周二和周四**：频率选每周，间隔 2，星期选 TU 和 TH。
- **每月最后一天**：频率选每月，按月内日期填 `-1`。
- **每月第二个星期二**：频率选每月，星期选 TU，设置位置填 `2`。

### 开始日期与时区 {#start-date-and-timezone}

**开始** 字段是序列的锚点，既决定触发的时刻，也决定最早可能的重复项。**时区** 请设为实际执行工作的人所在的 IANA 时区。Specivo 在夏令时切换前后保持钟表时间不变：设为周一 09:00 的模板，冬夏两季都会在当地时间 09:00 触发。

### 锚定模式 {#anchor-mode}

**锚定模式** 是最关键的行为选项：

**固定**（默认）
: 每个重复项都在排定的日历日期触发，不管上一个实例是否已关闭。如果生成任务错过了某次运行（停机、维护），下次运行时会把所有逾期的重复项一并补建，它们会堆积起来。适用于必须在特定日期发生的日历驱动事件，如站会、周报、冲刺（Sprint）相关会议。

**灵活**
: 只有上一个实例关闭后（状态属于“完成”或“已关闭”类别），才会创建下一个重复项。任一时刻最多只有一个未关闭的实例。适用于“做完上一次才有必要再做”的例行工作，如数据库维护、安全审计、一次只做一轮的评审周期。

锚定模式为 **灵活** 时，会多出一个 **基准日期** 选项，用来决定下一个重复项从哪里开始算：

- **排期日期**：从上一个重复项*原本应该*发生的时间起算。延迟关闭实例不会把整个序列往后推。
- **完成日期**：从上一个实例实际关闭的时间起算。当两次之间的间隔比日历日期更重要时适用。

### 提前生成时间 {#creation-lead-time}

**提前生成时间（天）** 控制工作项提前多久生成。默认为 30 天：后台任务大约每小时运行一次，把未来 30 天内到期、尚未生成的工作项都创建出来。想让工作项更早出现就调大，只想在临近到期时才出现就调小。

## 工作项模板 {#the-issue-template}

表单下半部分定义每个生成的工作项长什么样。

| 字段 | 作用 |
|---|---|
| **主题** | 工作项标题，支持[日期宏](#date-macros) |
| **追踪器** | 工作项类型（**Bug**（缺陷）、**Feature**（功能）、**Task**（任务）等） |
| **状态** | 初始状态；保持“跟踪器默认值”则使用追踪器配置的默认状态 |
| **优先级** | 初始优先级 |
| **默认指派人** | 工作项创建时指派给谁 |
| **描述模板** | 工作项正文，同样支持日期宏 |

### 沿用与重置 {#carry-over-and-reset}

**沿用与重置** 区域控制哪些模板值会应用到每个生成的实例：

- **沿用描述**：把描述模板应用到生成的工作项（默认开启）。
- **沿用指派人**：把生成的工作项指派给默认指派人（默认开启）。
- **沿用元数据**：把模板元数据应用到生成的工作项（默认开启）。
- **沿用预估工时**：按模板设置预计工时（默认开启）。
- **重置清单**：如果模板元数据包含布尔（清单式）字段，每个新实例都将其重置为未勾选。适用于每次都要从头开始的重复检查清单。

### 指派人轮换 {#assignee-rotation}

除了把每个实例都指派给同一个人，你还可以在一组成员之间**轮换**。选择要轮换的成员后，Specivo 会把每个新重复项指派给列表中的下一个人，到末尾后回到开头。同时设置了轮换和默认指派人时，以轮换为准。

## 日期宏 {#date-macros}

模板的 **主题** 和 **描述** 支持日期宏，宏会展开为每个重复项的本地日期（按模板所设时区）。这样生成的工作项彼此可区分：不再是十个一模一样的“Status report”，而是“Status report — 18 June 2026”、“Status report — 25 June 2026”……依次排列。

| 宏 | 展开为 | 示例（2026 年 6 月 18 日） |
|---|---|---|
| `{{year}}` | 四位年份 | `2026` |
| `{{quarter}}` | 带 Q 前缀的季度 | `Q2` |
| `{{month}}` | 月份全名 | `June` |
| `{{month_num}}` | 两位月份数字 | `06` |
| `{{day}}` | 两位日期 | `18` |
| `{{weekday}}` | 星期全名 | `Thursday` |

月份和星期名称会按工作区语言本地化。工作区设为法语时，`{{month}}` 输出 `juin`；设为泰语时输出 `มิถุนายน`。

!!! note "`{{quarter}}` 已经自带 Q"
    请写 `{{quarter}} {{year}} review`，不要写 `Q{{quarter}} {{year}} review`。该宏本身就输出 `Q2`，后一种写法会得到 `QQ2 2026`。

例如，主题为 `{{weekday}} standup — {{day}} {{month}} {{year}}` 时，2026 年 6 月 18 日那一次重复项会生成 `Thursday standup — 18 June 2026`。

未知的宏名称会原样保留在输出中，所以 `{{mnth}}` 这类拼写错误会直接显示出来，而不会悄无声息地消失。

## 生成机制 {#how-generation-works}

后台任务大约每小时运行一次，生成预生成窗口内到期、尚未创建的工作项。这个任务具有以下特点：

- **幂等**：运行两次不会产生重复。
- **自动补建**：如果某次生成被错过（例如在计划维护期间），下次运行会一次性创建所有逾期的重复项（固定模式下）。
- **故障隔离**：某个模板出问题，不会影响其他模板的生成。

每个生成的工作项在 **动态** 标签页中都有一条 **“从重复模板创建”** 记录，并附带指向该模板的链接。这就是来源追溯链：你随时都能查到某个工作项是由哪个模板生成的。

## 查看重复模板 {#viewing-a-pattern}

在 **重复任务** 列表中点击模板名称，打开详情页。详情页显示：

- **排期**：配置的规则、时区、锚定模式和提前生成时间。
- **模板**：主题、沿用设置和轮换名单。
- **即将到来的重复项**：预生成窗口内接下来的排定日期。管理者可以点击任一重复项旁边的 **跳过** 把它排除。
- **实时预览**：可刷新的视图，显示引擎接下来会生成的重复项。
- **已生成实例**：该模板生成过的所有工作项，列出各自的状态和排定的重复项日期。

## 编辑重复模板 {#editing-a-pattern}

在详情页点击 **编辑**。表单上有一条提示：**编辑模板只影响未来的实例**。已生成的工作项保留创建时的值，只有尚未生成的重复项会采用新的模板或排期。

如果你需要让改动从某个未来日期起生效，同时保留此前的历史，请让项目管理者或 AI 智能体（AI agent）通过 API 执行一次**“此次及以后”拆分**：在所选重复项之前结束旧序列，并从该点开始启用一个新模板。

## 跳过单个重复项 {#skipping-a-single-occurrence}

在模板详情页，**即将到来的重复项** 列表中每个排定日期旁都有 **跳过** 按钮。跳过会把这一个日期从序列中移除，对应的工作项不再创建。如果该重复项的工作项已经生成且未被动过（仍处于未关闭状态、没有任何进展记录），它会被删除。灵活模式下，被跳过的重复项不算作完成。

## 停用与删除重复模板 {#disabling-and-deleting-a-pattern}

- **停用**：取消勾选 **已启用** 并保存。不再生成新工作项，但已有工作项和模板历史都会保留。随时可以重新启用。
- **删除**：删除模板。已生成的工作项会保留（指向模板的链接被清除）；跳过和覆盖等例外记录会被删除。
