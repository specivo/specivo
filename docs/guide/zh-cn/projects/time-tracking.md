# 工时记录 {#time-tracking}

在 Specivo 中，你可以为自己做的工作 **记录工时**：把花在某个工作项（Issue）或项目上的小时数记下来，并标明活动类型。已记录的工时会汇总到报表中，方便你了解精力花在了哪里，并与预计工时对比。

## 谁能做什么 {#who-can-do-what}

项目中的工时记录由 3 项角色权限控制：

| 权限 | 允许的操作 |
|---|---|
| **查看工时记录** | 查看工时：项目的“时间”区域、工作项的时间选项卡和已记录工时合计、版本的已记录工时合计，以及计费工时报表。没有这项权限就看不到任何工时记录，连自己的也看不到。 |
| **记录工时** | 手动或用计时器记录工时，并编辑或删除自己的工时记录（前提是你能看到它们）。 |
| **编辑任何工时记录** | 编辑或删除项目中任何人的工时记录。 |

默认情况下，**Manager**（管理者）拥有全部 3 项权限，**Developer**（开发者）和 **Agent**（智能体）可以查看和记录工时，**Reporter**（报告者）和内置的 **Non member**（非成员）角色则一项都没有。即使没有 *编辑任何工时记录* 权限，只要在项目中拥有 *记录工时* 权限，你仍然可以编辑或删除自己的工时记录。管理员可以执行所有操作。你无权使用的按钮（*记录工时*、工作项上的工时记录表单、编辑控件）会被隐藏。

计费工时报表使用的项目 **计费费率** 通过 REST API 管理。创建、修改或删除费率需要 **管理项目设置** 权限，列出费率需要 **查看工时记录** 权限。没有单独的计费权限。

## 为工作项记录工时 {#log-time-against-an-issue}

打开工作项，添加一条工时记录：填写 **小时** 数、**日期**、**活动**，以及可选的评论。最常见的做法是把工时记在工作项上，这样投入的时间就对应到一项具体的工作。如果某些工作无法对应到单个工作项，也可以把工时记在项目上。

### 活动 {#activities}

每条工时记录都带有一个 **活动**，报表可以据此按类型拆分工时：

| 活动 | 适用于 |
|---|---|
| **开发** | 编写和修改代码（默认值） |
| **设计** | UI、UX 和设计工作 |
| **测试** | QA、编写测试、验证 |
| **会议** | 规划、站会、评审 |
| **支持** | 帮助用户、答复请求 |

默认选中 **开发**，所以最常见的情况可以少点一次。

## 用计时器计时 {#time-it-with-a-timer}

不必自己累加小时数，可以让计时器来计。打开工作项，点击工作项编号旁边的 **启动计时器**（需要在项目中拥有 *记录工时* 权限）。同一时间你只能有一个计时器：

- 计时器运行期间，每个页面的页头都会显示工作项编号和已用时间，工作项页面上会显示 *计时器运行中*。点击页头中的计时器，可以查看对应的工作项及其主题。
- **停止并记录** 会让你选择 **活动**（已预选默认活动）并填写可选的评论，然后在该工作项上写入一条日期为今天的工时记录。已用时间四舍五入到 0.01 小时；忘记停止的计时器会被封顶（上限为 12 小时，除非管理员改过），并在评论中注明。
- **放弃** 会丢弃计时器，不写入任何内容。

如果点击 **启动计时器** 时，另一个工作项上已有计时器在运行，Specivo 会先询问：**记录并启动** 会以默认活动写入旧计时器的工时，**放弃并启动** 则直接丢弃它，随后新计时器开始计时。如果想用其他活动或加上评论来记录旧计时器的工时，请先在页头中停止它。

停止计时器或启动另一个计时器时，系统会重新检查正在运行的计时器：如果在此期间你已失去在其项目或工作项上记录工时的权限，计时器会被丢弃，不写入任何工时。点击 **记录并启动** 后，工作项页面上会出现一条简短的提示，说明旧计时器的处理结果：在哪个工作项上记录了多少小时，或者它已被丢弃。如果你已无法查看该工作项，页头仍会显示它的编号，但不显示主题。

AI 智能体（AI agent）可以通过 `specivo_timer` 工具操作同一个计时器（参见[智能体能做什么](../ai-agents/capabilities.md)）。

## 通过提交记录工时 {#log-time-from-a-commit}

如果项目配置了[仓库集成](../integrations/repositories.md)，并且开启了提交命令和工时记录，提交信息也可以用来记录工时：`ACME-12 @1h30m`（也可以写 `@2h`、`@90m` 或 `@1.5h`）会以默认活动为提交的作者在 ACME-12 上记录这段工时，日期为提交当天。作者是指已验证邮箱与提交邮箱一致的 Specivo 账户，并且需要在项目中拥有 *记录工时* 权限。时间要紧跟在工作项编号之后，写在同一行；0 会被忽略，一次提交中为同一个工作项记录超过 24 小时的，会被截为 24 小时。详见[提交命令](../integrations/repositories.md#commit-commands)。

## 预计工时与已用工时 {#estimate-versus-spent}

工作项除了实际 **已记录** 的工时，还带有 **预计工时**，以及原始预估和剩余预估。对比两者就能判断一项工作是否按计划推进：预计 8 小时的工作项已记录 12 小时却仍未关闭，就值得留意。完整的字段列表见[什么是工作项？](../issues/index.md)。

这三项都由有权编辑该工作项的人手动设置，以小时和分钟为单位，可以在工作项侧边栏或编辑表单中填写。预计工时调整后，**原始预估** 仍保留最初的计划值；**剩余预估** 是剩下的工作量，记录工时不会让它减少。工作项的 **时间** 选项卡会把已记录的小时数合计出来，与这三项并排显示。

## 项目的时间区域 {#the-project-time-area}

每个项目都有一个 **时间** 区域，列出工时记录并汇总成报表：按活动、按人员以及按日期范围合计。这样 [Manager](index.md) 就能看到工时在项目中的分布情况。

!!! note "谁能看到谁的工时"
    默认情况下，拥有 **查看工时记录** 权限的人可以看到所有工时记录。如果角色设置为 **仅自己的工时记录**（参见[角色能看到什么](index.md#what-a-role-can-see)），该角色的成员只能看到自己记录的工时，在时间区域、工作项、版本合计和报表中都是如此。拥有多个角色的人，以其中范围最宽的设置为准。

    记在你无法查看的工作项（例如别人的私有工作项）上的工时，在所有地方都会被排除：列表、各项合计和计费工时报表中都不包含，因此数字不会泄露隐藏工作项上的工作。直接记在项目上、未关联工作项的工时不受影响。你自己的工时记录始终对你可见，即使所在的工作项你已无法查看。
