# 工时记录 {#time-tracking}

Specivo 可以为你所做的工作 **记录工时**：在工作项（Issue）或项目上记录花费的小时数，并标注活动类型。记录的工时会汇总到报表中，让你看清精力花在哪里，并与预计工时对比。

## 谁能做什么 {#who-can-do-what}

项目中有三项角色权限控制工时记录：

| 权限 | 允许 |
|---|---|
| **查看工时记录** | 查看工时：项目的时间区域、工作项的工时标签页和已记录总计、版本的已记录总计，以及可计费工时报表。没有此权限就看不到任何记录，连自己的也看不到。 |
| **记录工时** | 手动或用计时器记录工时，以及编辑或删除自己的记录（前提是你能看到它们）。 |
| **编辑/删除所有工时记录** | 编辑或删除项目中任何人的记录。 |

默认情况下，**Manager**（管理者）拥有全部三项权限，**Developer**（开发者）和 **Agent**（代理）可以查看和记录工时，**Reporter**（报告者）和内置的 **Non member**（非成员）角色则没有任何权限。没有 *编辑/删除所有工时记录* 权限时，只要在项目中有 *记录工时* 权限，仍然可以编辑或删除自己的记录。管理员可以执行所有操作。无权使用的按钮（*记录工时*、工作项上的记录工时表单、编辑控件）会被隐藏。

项目的 **计费费率** 用于可计费工时报表，通过 REST API 管理。创建、修改或删除费率需要 **管理项目设置** 权限，列出费率需要 **查看工时记录** 权限。没有单独的计费权限。

## 在工作项上记录工时 {#log-time-against-an-issue}

打开工作项，添加一条工时记录：填写 **小时**、**日期**、**活动**，以及可选的备注。在工作项上记录是最常见的情形，因为它把精力和具体工作挂钩。对于无法归入某个工作项的工作，也可以在项目级别记录工时。

### 活动 {#activities}

每条记录都标注一个 **活动**，报表就能按类型拆分精力：

| 活动 | 用于 |
|---|---|
| **Development**（开发） | 编写和修改代码，默认选项 |
| **Design**（设计） | UI、UX 和设计工作 |
| **Testing**（测试） | QA、编写测试、验证 |
| **Meetings**（会议） | 规划、站会、评审 |
| **Support**（支持） | 帮助用户、响应请求 |

默认选中 **Development**，常见情形少点一次。

## 用计时器计时 {#time-it-with-a-timer}

不必自己累加小时数，让计时器来算。打开工作项，在编号旁选择 **启动计时器**（需要项目中的 *记录工时* 权限）。同一时间只能有一个计时器：

- 计时器运行期间，每个页面的页头都会显示工作项编号和已用时间，工作项页面显示 *计时器运行中*。点击页头中的计时器可查看该工作项及其主题。
- **停止并记录** 会询问 **活动**（默认活动已预选）和可选的备注，然后在该工作项上写入一条日期为今天的工时记录。已用时间四舍五入到百分之一小时；一直没停的计时器会被截断（上限为 12 小时，除非管理员改过），并在备注中注明。
- **放弃** 直接丢弃计时器，不写入任何内容。

如果你选择 **启动计时器** 时另一个工作项上已有计时器在运行，Specivo 会先询问：**记录并启动** 用默认活动写入其工时，**放弃并启动** 则直接丢弃，然后启动新计时器。要用其他活动或备注记录旧计时器，请先在页头中停止它。

停止计时器或启动另一个计时器时，会再次检查正在运行的计时器：如果你在此期间失去了在其项目或工作项上记录工时的权限，计时器会被丢弃，不写入任何工时。**记录并启动** 之后，工作项页面会短暂提示旧计时器的处理结果：在哪个工作项上记录了多少小时，或已被丢弃。如果你已看不到该工作项，页头仍显示其编号，但不显示主题。

AI 智能体（AI agent）可以通过 `specivo_timer` 工具操作同一个计时器（见 [智能体能做什么](../ai-agents/capabilities.md)）。

## 从提交记录工时 {#log-time-from-a-commit}

项目配置了 [代码仓库集成](../integrations/repositories.md)、并开启提交命令和工时记录后，提交信息也能记录工时：`ACME-12 @1h30m`（也可以写 `@2h`、`@90m` 或 `@1.5h`）会以默认活动在 ACME-12 上为提交作者记录这段时间，日期为提交当天。作者是指已验证邮箱与提交邮箱一致的 Specivo 账户，且需要项目中的 *记录工时* 权限。时间紧跟工作项编号，写在同一行；零会被忽略，同一提交中单个工作项超过 24 小时会截断为 24 小时。详见 [提交命令](../integrations/repositories.md#commit-commands)。

## 预计与已用 {#estimate-versus-spent}

工作项带有 **预计工时**（预计小时数，含原始预计和剩余预计），以及实际 **记录** 的工时。两者对比可以看出工作是否正常推进：一个预计 8 小时、已记录 12 小时却仍未关闭的工作项，值得留意。完整字段见 [什么是工作项？](../issues/index.md)。

## 项目的时间区域 {#the-project-time-area}

每个项目都有一个 **时间** 区域，列出工时记录并汇总为报表（按活动、按人员、按日期范围的总计），让 [Manager](index.md) 看清精力在项目中的分布。

!!! note "谁能看到谁的工时"
    默认情况下，拥有 **查看工时记录** 权限的人都能看到所有记录。设为 **仅自己的工时记录** 的角色（见 [角色能看到什么](index.md#what-a-role-can-see)）只能看到角色持有者自己记录的工时：在时间区域、工作项、版本总计和报表中都是如此。拥有多个角色的人，按其中最宽松的设置生效。

    在你看不到的工作项（例如别人的私有工作项）上记录的工时，会在所有地方被排除：列表、各项总计和可计费工时报表都不包含它，因此数字不会泄露隐藏工作项上的工作。直接记录在项目上、不关联工作项的工时不受影响。你自己的记录对你始终可见，即使所在的工作项你已经看不到了。
