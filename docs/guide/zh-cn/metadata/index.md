# 什么是元数据？ {#what-is-metadata}

**元数据** 是附加在工作项（Issue）上、核心字段之外的结构化带类型数据。核心字段覆盖每个工作项都需要的基本信息：主题、状态、负责人、优先级；元数据则记录团队额外关心的事实：git 分支、故事点估算、严重程度、发布日期。每条元数据都是一个有名字的 **键**，对应一个带类型的 **值**，由 [架构](schemas.md) 定义，这样同一字段在所有使用它的工作项上都保持一致。

## 为什么不直接写在描述里？ {#why-not-just-write-it-in-the-description}

你*当然可以*在描述里写上“branch: feature/login, 5 points, severity major”。但元数据是 **带类型的结构化数据**，而不是自由文本，所以更好用：

- **一致。** 所有人以同样的方式填写同样的字段，不会出现这个工作项写“5 pts”、下一个写“five story points”的情况。
- **可筛选。** 工作项列表可以 [按元数据筛选](values.md)，你可以一次列出所有 `severity = critical` 的工作项，或所有涉及某个分支的工作项。描述里的自由文本做不到这一点，至少做不可靠。
- **有校验。** `enum` 字段只接受预设的选项，`number` 字段只接受数字。错误的值在输入时就会被拦下，而不是事后才发现。

## 字段类型 {#field-types}

架构为每个字段定义一种类型，类型决定了你能输入什么，以及 Specivo 如何校验。

| 类型 | 存放内容 | 示例 |
|---|---|---|
| **字符串** | 单行自由文本 | `component` = `Backend` |
| **数字 / 整数** | 一个数值 | `story_points` = `5` |
| **日期** | 一个日历日期 | `publish_date` = `2026-07-01` |
| **枚举** | 从固定列表中选一项 | `severity` = `critical` |
| **数组** | 一组值（可添加或删除条目） | `branches` = `[main, feature/login]` |

要在一个键下记录多个值，比如多个 git 分支、一组标签、一串拉取请求，就用数组字段，而不必把它们硬塞进一个字符串里。

## 元数据在工作项上如何显示 {#how-metadata-appears-on-an-issue}

当某个架构适用于一个工作项时，它的字段会在工作项详情页上单独成一区，与核心字段并列显示。填写方式和其他字段一样：输入字符串、选择日期、选取枚举值，或者向数组添加条目。留空的字段就保持为空。
