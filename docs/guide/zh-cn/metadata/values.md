# 使用元数据值 {#working-with-metadata-values}

一旦某个[元数据架构](schemas.md)应用到了工作项（Issue），就可以填写它的[元数据](index.md)字段了。本页介绍如何查看和设置这些值、编辑列表（数组）字段，以及按元数据筛选工作项列表。

## 查看元数据 {#viewing-metadata}

打开任意工作项。元数据字段在工作项详情页中单独占一个区域，与核心字段并列显示。尚未填写的字段显示为空。

每个字段都以其**名称**作为标签。如果架构中为字段定义了标题，那么在工作项页面、工作项历史记录、搜索筛选条件、REST API 以及 MCP 中都会显示该标题，标题用什么语言写就显示什么。没有标题的字段会以可读形式显示其键名（`story_points` 显示为“Story Points”）。通过[导入](../install/importing.md)带入的字段保留在旧系统中的名称。

存放**人员**或**版本**的字段会显示对应的人员名或版本名，而不是内部 ID，前提是你有权限查看；否则显示存储的原始值。

## 设置值 {#setting-a-value}

编辑工作项，按字段类型分别设置：

- **字符串**：直接输入文本（例如 `component` = `Backend`）。
- **数字/整数**：输入数值（例如 `story_points` = `5`）。
- **日期**：在日期选择器中选择日期。
- **枚举**：从字段的固定选项列表中选择一项（例如 `severity` = `major`）。

Specivo 会即时校验：枚举字段只接受允许的选项，数字字段会拒绝非数字输入。保存工作项即可存储这些值。

## 编辑数组字段 {#editing-array-fields}

**数组**字段用于存放一组值：多个分支、几个标签、一批拉取请求。条目逐个添加，不再需要的随时删除。例如 `branches` 字段起初可能只有 `main`，随着工作分散到多个分支，逐渐变成 `main`、`feature/login`。数组字段可以和工作项上的其他字段随意搭配使用，没有任何限制。

!!! note "计算字段会自动填充"
    [项目派生（计算）字段](schemas.md#project-derived-computed-fields)会在每个工作项上自动显示值，并且是**只读**的：无需设置，也无法覆盖。它的值来自项目，因此工作项[移动到其他项目](../issues/updating.md#move-an-issue-to-another-project)后，值也会自动更新。

## 按元数据筛选工作项列表 {#filtering-issue-lists-by-metadata}

元数据的价值在跨工作项搜索时才真正体现出来。工作项列表可以用“键=值”匹配来**按元数据筛选**：

- 先选元数据键，再选要匹配的值。例如 `severity = critical` 只看严重级别为 critical 的缺陷，`content_status = draft` 找出所有仍处于草稿状态的内容。
- 对于**数组**字段，只要数组**包含**该值即匹配。用 `feature/login` 筛选 `branches`，会返回分支列表中含有 `feature/login` 的所有工作项，即使它们还列出了其他分支。

这正是相比自由文本的优势：值有类型、保持一致，所以筛选结果恰好就是你想要的那些工作项。

你也可以直接从任意工作项进入按元数据筛选的搜索。当工作项带有**数组**类型的元数据值（例如 `branches` 或 `tags` 字段）时，每个值都会在工作项的元数据区域显示为**可点击的标签**。点击标签会打开一个搜索，按同一个值筛选，范围覆盖**你能访问的所有项目**。这样不必从项目列表入手，就能快速找到带有某个分支、标签或类别的全部工作项。

!!! tip "AI 智能体也能设置元数据"
    接入的 AI 智能体（AI agent）可以通过内置的 MCP 服务器读取和更新元数据，例如在工作过程中向 `commits` 数组追加提交哈希，或给工作项打标签。参见 [AI 智能体工作流](../ai-agents/workflows.md)。
