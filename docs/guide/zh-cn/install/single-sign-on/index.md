# 单点登录 {#single-sign-on}

单点登录（SSO）让用户直接用他们在身份提供商（IdP，例如 Keycloak、authentik 或 Microsoft Entra ID）已有的账户登录 Specivo。

本页说明它的工作原理以及每个设置的作用。具体某个提供商的操作步骤，请看对应页面：

- [Keycloak](keycloak.md)
- [authentik](authentik.md)
- [Microsoft Entra ID](entra-id.md)
- [Okta、Google、Zitadel 和 Authelia](other-providers.md)

## 支持范围 {#what-specivo-supports}

- **仅支持 OpenID Connect**。Specivo 是 OpenID Connect 的*依赖方*（relying party）：它向你的 IdP 询问“这个人是谁”。Specivo 自身从不充当 IdP，也不会为其他应用签发身份。不支持 SAML。如果你的 IdP 只支持 SAML，请在它前面加一层能把 SAML 桥接到 OpenID Connect 的 IdP（Keycloak 和 authentik 都可以）。
- **可同时配置多个提供商**。每个提供商在登录页面上都有自己的按钮。
- **本地账户继续保留**。除非你隐藏或限制密码登录，密码仍然可用，而且你始终可以以管理员身份重新进入。见 [重新进入](../configuration.md#single-sign-on-getting-back-in)。
- **仅限真人用户**。服务账户（AI 智能体使用的账户）永远不能通过 SSO 登录。API 密钥不受 SSO 影响。
- **没有目录同步**。Specivo 不支持 SCIM 或 LDAP。用户在首次登录时出现，离开则按 [用户离职处理](#offboarding-people) 中的步骤进行。

## 开始之前 {#before-you-start}

1. **通过 HTTPS 在公开地址提供 Specivo 服务**。大多数 IdP 拒绝纯 `http://` 的重定向地址，Specivo 也拒绝 `http://` 的 IdP，除非你显式允许（见 [环境中的设置](#settings-in-the-environment)）。
2. **把 `APP_URL` 设为该公开地址**，例如在 `.env` 中写 `APP_URL=https://specivo.example.com`，然后重新创建容器（`docker compose up -d`）。Specivo 交给 IdP 的每个地址都由 `APP_URL` 构造而来，从不从请求中获取，所以放在反向代理后面时无需其他改动。请先做这一步：`APP_URL` 配错是首次登录失败最常见的原因。
3. **不要让代理的访问日志记录查询字符串**。从 IdP 返回的重定向在查询字符串中带有一次性的 `code` 和 `state`。自带的 nginx 记录路径时不含查询字符串。如果前面还有另一层代理（Caddy、Traefik、Cloudflare、负载均衡器），也要把它的访问日志配置为不记录查询字符串，至少对 `/auth/oidc/` 要这样。关于这类代理后面按地址限速的问题，见 [代理后的客户端地址](../configuration.md#client-addresses-behind-a-proxy)。
4. **确认你能用密码以管理员身份登录**。测试期间保留这个账户。

## 设置提供商：步骤概览 {#setting-up-a-provider-the-outline}

每个 IdP 的步骤都一样，只是界面不同。

1. 在 Specivo 中打开 **管理 → 单点登录**，点击 **+ 新建提供商**。选择一个 **标识串**（小写字母、数字和 `-`，2 到 40 个字符），例如 `keycloak`。**连接** 卡片会显示由它构造出的两个地址：

    | 地址 | 格式 |
    |---|---|
    | 重定向 URI | `{APP_URL}/auth/oidc/{slug}/callback/` |
    | 后端通道注销 URI | `{APP_URL}/auth/oidc/{slug}/backchannel-logout/` |

    例如 `https://specivo.example.com/auth/oidc/keycloak/callback/`。末尾的斜杠是地址的一部分。如果 Specivo 通过路径前缀（`STEALTH_PREFIX`）提供服务，这些地址以及下文的注销后地址中，前缀紧跟在 `{APP_URL}` 之后。**连接** 卡片显示的是包含前缀的准确地址，请直接从那里复制。

2. 在 IdP 中为 Specivo 创建一个客户端（即“应用”），并**完全按照显示的内容**注册重定向 URI。不要使用通配符。如果 IdP 要求填写注销后重定向地址，注册 `{APP_URL}/login/?logged_out=1`。如果需要后端通道注销，也把后端通道注销 URI 注册上。
3. 把 IdP 的 **颁发者**、**客户端 ID** 和 **客户端密钥** 复制到 Specivo。
4. 保存，然后点击 **测试连接**。Specivo 会获取 IdP 的发现文档和签名密钥，并报告它找到了什么（见 [测试连接](#test-connection)）。
5. 勾选 **已启用（显示在登录页面）** 并保存。新建的提供商默认是禁用的，这样不会有人看到一个配置了一半的按钮。
6. 打开一个隐私浏览窗口，通过新按钮登录。

!!! warning "更改标识串会改变地址"
    标识串是重定向 URI 和后端通道注销 URI 的一部分。如果重命名了提供商，要在 IdP 处同时更新这两个地址，否则通过该提供商登录会失败。如果该提供商在 **将登录页面重定向到** 中被选中，那个设置会自动跟随新的标识串。

## 提供商设置 {#provider-settings}

提供商表单分为五张卡片。下面的表格列出每个字段。

### 连接 {#connection}

| 字段 | 作用 |
|---|---|
| 按钮文字 | 登录按钮上显示的名称：“使用 *标签* 登录”。 |
| 标识串 | 上述地址的组成部分。必须唯一。 |
| 颁发者 | IdP 的颁发者地址，逐字符复制。它必须与 IdP 公布的 `issuer` 以及每个 ID 令牌（ID token）中的 `iss` 完全一致。多一个末尾斜杠、用 `http` 代替 `https`，或者主机名不同，都会导致失败。 |
| 发现 URL | 可选。留空表示 `{issuer}/.well-known/openid-configuration`。只有当 IdP 把配置发布在其他位置时才需要设置。 |
| 客户端 ID | 在 IdP 注册的客户端 ID。 |
| 客户端认证 | Specivo 在令牌端点证明自身身份的方式：`client_secret_basic`（默认）、`client_secret_post`，或 `none`（仅依赖 PKCE 的公共客户端）。除非 IdP 的文档另有说明，请使用 `client_secret_basic`。 |
| 客户端密钥 | 见 [客户端密钥](#the-client-secret)。选 `none` 时不使用。 |
| 作用域 | 以空格分隔。默认 `openid profile email`。`openid` 是必需的，且始终放在最前面发送。如果 IdP 需要额外的作用域才会释放某个声明，就加上 `groups` 或其他作用域。 |
| 额外登录参数 | 可选的 `prompt`、`domain_hint`、`login_hint`、`acr_values` 和 `max_age`，会附加到登录请求上。这里不能设置其他参数。设置了 `max_age` 时，ID 令牌中的 `auth_time` 距今不得超过 `max_age` 秒（加上 `SSO_CLOCK_SKEW_SECONDS`），否则登录会被拒绝并返回 `sso_token_invalid`。无论这里如何设置，从个人资料页点击 **关联** 时始终发送 `prompt=login` 和 `max_age=0`。 |
| 已启用 | 在登录页面显示按钮。机密客户端没有密钥时无法启用。关闭它会让所有会话来自该提供商的用户退出登录（见 [会话](#sessions-and-logout)）。 |
| 按钮顺序 | 数字越小越靠前。 |

Specivo 始终使用带 PKCE（`S256`）、`state` 和 `nonce` 的授权码流程，对机密客户端也是如此。你的 IdP 必须允许 `S256` 的 PKCE。ID 令牌必须用非对称算法（RS256、PS256、ES256 等）签名。用共享密钥签名的令牌（`HS256`）一律拒绝。

### 客户端密钥 {#the-client-secret}

密钥是只写的。Specivo 只显示它的状态：

| 状态 | 含义 |
|---|---|
| 已存储（加密） | 已保存在数据库中，用由 `SECRET_KEY` 派生的密钥加密。 |
| 从环境变量读取 | 提供商指向一个已设置的环境变量。 |
| 未设置环境变量 | 提供商指向一个容器中不存在的变量。 |
| 不允许使用此环境变量名 | 名称不以 `SPECIVO_SSO_SECRET_` 开头。Specivo 从不读取它。 |
| 更改 SECRET_KEY 后无法读取：请重新输入 | 见下文。 |
| 未设置 | 没有任何配置。 |
| 公共客户端无需设置 | 客户端认证为 `none`。 |

选择其中一种来源：

- **存储在 Specivo 中**。把密钥粘贴到字段里。之后保存时留空即保留当前密钥。
- **从环境变量读取**。输入一个以 `SPECIVO_SSO_SECRET_` 开头、后接大写字母、数字和下划线的名称，例如 `SPECIVO_SSO_SECRET_KEYCLOAK`。在 `.env.local` 中设置它并重新创建容器。每个处理请求的 Specivo 容器都要设置。其他名称会被拒绝，因此提供商设置永远无法被用来读取 `SECRET_KEY` 或 `DATABASE_URL`。这样密钥既不进数据库，也不进数据库备份。

!!! warning "轮换 SECRET_KEY 会让已存储的密钥无法读取"
    已存储的密钥用由 `SECRET_KEY` 派生的密钥加密。如果更改了 `SECRET_KEY`，所有已存储的客户端密钥都会变得无法读取，提供商列表会显示 **无法读取，请重新输入**。打开每个提供商，重新粘贴密钥并保存。从环境变量读取的密钥不受影响。

### 登录策略 {#sign-in-policy}

| 字段 | 作用 |
|---|---|
| 首次登录时创建账户 | 即时开通账户（JIT provisioning）。**默认关闭**。见 [谁会获得账户](#who-gets-an-account)。 |
| 现有账户 | 已有 Specivo 账户的用户如何与其 IdP 身份关联：由用户自行关联（默认），或按已验证的邮箱自动关联。见 [关联现有账户](#linking-an-existing-account)。 |
| 此提供商确实会验证邮箱地址 | 告诉 Specivo 可以相信 `email_verified` 声明。自动关联需要它。默认关闭。**对 Microsoft Entra ID 绝不要开启**。 |
| 允许的邮箱域名 | 每行一个域名。留空允许所有域名。见 [限制登录人员](#limiting-who-can-sign-in)。 |
| 最长会话时长（小时） | 通过该提供商登录的会话最长持续时间，1 到 168（一周）。默认 24。见 [会话](#sessions-and-logout)。 |

### 声明 {#claims}

ID 令牌中的哪些声明（claim）用来填充 Specivo 个人资料。字段留空则使用标准声明。

| 字段 | 默认值 | 用途 |
|---|---|---|
| 用户名声明 | `preferred_username` | 新建账户的登录名。 |
| 邮箱声明 | `email` | 电子邮件地址。 |
| 姓名声明 | `name` | 显示名称。 |
| 语言声明 | `locale` | 界面语言。`th`、`th-TH` 和 `th_TH` 都映射为 `th`。Specivo 没有对应翻译的值会被忽略。 |
| 组声明 | `groups` | 用于 [组映射](#groups-and-roles) 的组或角色。可以是点分路径，例如 `groups`、`realm_access.roles` 或 `resource_access.specivo.roles`。 |
| 同时从 userinfo 端点读取声明 | 关闭 | 把 IdP 的 userinfo 响应合并到声明中。当 IdP 没把声明放进 ID 令牌时使用。userinfo 中的 subject 必须与 ID 令牌一致，否则登录会被拒绝。 |

!!! warning "如果依赖邮箱验证，请保持邮箱声明为 `email`"
    `email_verified` 只为标准的 `email` 声明背书。如果你把 **邮箱声明** 设为其他值（`upn` 或自定义属性），即使开启了 **此提供商确实会验证邮箱地址**，Specivo 也始终把该地址视为未验证。于是邮箱域名列表会拒绝所有人，用户的 Specivo 邮箱不再跟随 IdP 更新，首次登录创建的账户带有未验证的邮箱，自动关联也永远不会生效。

### 组 {#groups}

必需的组、管理员组和组映射。见 [组与角色](#groups-and-roles)。

### 会话检查 {#session-check}

| 字段 | 作用 |
|---|---|
| 续期会话时向提供商核查会话 | **默认开启**。Specivo 在续期会话之前（用户活跃时每 15 分钟一次）会询问 IdP 该用户是否仍可登录。在 IdP 处被禁用、删除或已退出的用户，会在下一次续期时失去 Specivo 会话。需要 IdP 发放刷新令牌；见 [会话检查](#the-session-check)。 |
| 无法连接提供商时 | **保留会话**（默认）：本次续期照常进行，下次再问。能够阻断 Specivo 与 IdP 之间流量的人可以借此保住会话，但永远不能超过 **最长会话时长**。**结束会话**：提供商宕机期间，来自该提供商的所有用户都会被退出登录。本地登录始终可用。 |

### 注销 {#logout}

| 字段 | 作用 |
|---|---|
| 退出 Specivo 时也在提供商处退出 | RP 发起的注销（RP-initiated logout），默认开启。见 [会话与注销](#sessions-and-logout)。 |
| 接受来自提供商的后端通道注销 | 默认关闭。见 [会话与注销](#sessions-and-logout)。 |
| 提供商结束会话时 | 后端通道注销结束什么：匹配的那个会话（默认）、该用户来自此提供商的所有会话，或该用户的全部会话及其 API 密钥。见 [后端通道注销会结束什么](#what-a-back-channel-logout-ends)。 |

## 测试连接 {#test-connection}

在已保存的提供商上点击 **测试连接**。Specivo 会立即获取发现文档和签名密钥，不保存任何内容，并显示：

- 找到的地址（授权、令牌、userinfo 和结束会话端点），
- IdP 报告的颁发者是否与你输入的一致，
- 可用的签名算法、IdP 提供的客户端认证方式，以及它公布了多少个签名密钥，
- IdP 是否宣告支持后端通道注销和刷新令牌授权，
- 会话是否在提供商处被核查，以最近一次登录的结果为准：**正常**、**不可用：提供商未发送刷新令牌**、**不可用：提供商拒绝了刷新令牌**，或者在开启检查后还没有人登录过时显示 **尚不清楚**。只有真实登录才能拿到刷新令牌，所以测试本身无法尝试，
- 对那些能用但很可能不是你想要的设置给出警告：IdP 没有宣告所选的客户端认证方式或 PKCE、开启了在提供商处退出但 IdP 没有结束会话端点、开启了后端通道注销但 IdP 不支持、开启了 userinfo 但 IdP 没有该端点、客户端密钥缺失、无法读取或指向了错误的环境变量，或者开启了会话检查却无法工作（见 [会话检查](#the-session-check)）。

测试不会让任何人登录。它证明 Specivo 能连上 IdP，而且颁发者正确；但它无法证明客户端 ID、密钥或重定向 URI 正确。只有真实登录才能验证这些。

## 用户如何登录 {#how-people-sign-in}

登录页面在密码表单上方为每个已启用的提供商显示一个 **使用 *标签* 登录** 按钮。IdP 确认用户身份后，Specivo 会启动自己的会话，与密码登录启动的会话是同一种。IdP 的令牌不会保留，只有 ID 令牌例外（加密后存放在会话中，以便退出登录时告知 IdP 结束哪个会话）。

Specivo 识别的身份是 **颁发者和 subject** 这一对：IdP 的地址加上用户在那里的永久 ID。它从不是邮箱地址。在 IdP 处修改某人的邮箱不会改变其 Specivo 账户归属，也没有人能通过把自己的邮箱改成别人的来接管账户。

### 谁会获得账户 {#who-gets-an-account}

对于没有关联账户的用户，Specivo 按以下顺序判断：

1. 如果（颁发者，subject）已关联到某个 Specivo 用户，该用户登录。
2. 否则，如果 [自动关联](#linking-an-existing-account) 适用，把该身份关联到匹配的用户。
3. 否则，如果开启了 **首次登录时创建账户**，则创建新账户。新账户没有密码、处于启用状态，登录名取自用户名声明（清理为小写字母、数字、`_` 和 `-`，名字已被占用时追加数字）。没有邮箱会中止创建（`sso_email_missing`）。邮箱已被其他账户使用也会中止（`sso_email_conflict`）：这时用户应改用密码登录，再从个人资料页关联账户。新账户永远不会通过邮箱与现有账户关联。
4. 否则拒绝登录，返回 `sso_account_not_provisioned`。

即时创建默认关闭。如果 IdP 放行的每个人都应该获得账户，就开启它；如果不是，请配合 [必需的组](#groups-and-roles) 或 [邮箱域名列表](#limiting-who-can-sign-in) 使用。

即使已关联，账户也可能被拒绝：已停用的账户、被管理员锁定的账户、仍在等待邮箱验证的账户，以及服务账户都不能通过 SSO 登录（`sso_account_disabled`）。多次输错密码导致的锁定不会阻止 SSO，因为它只保护密码登录。

### 关联现有账户 {#linking-an-existing-account}

大多数部署一开始用的是本地账户。把它们与 IdP 关联有两种方式。

**手动（默认）**。用户用密码登录，打开 **个人资料 → 已关联账户**（在账户菜单中），点击 **关联 *标签***。即使用户在 IdP 处已有会话，IdP 也会要求再次登录（Specivo 发送 `prompt=login` 和 `max_age=0`），因此一台在 IdP 处保持登录状态的浏览器不能被用来关联别人的账户。在 IdP 登录后，用户回到个人资料页，账户已完成关联。从此登录页面上的按钮对他们就可用了。之后可以点击 **断开关联**，但前提是保留另一种登录方式（密码或另一个已关联账户）。管理员可以在用户的管理页面断开任意身份的关联。断开关联会结束通过该身份启动的会话。

一个身份只能属于一个用户（`sso_identity_in_use`），一个用户在每个提供商只能关联一个账户（`sso_provider_already_linked`）。

**按已验证邮箱自动关联**。选择 **按已验证的邮箱自动关联（管理员除外）** 并开启 **此提供商确实会验证邮箱地址**。用户首次登录时，Specivo 只在**以下条件全部满足**时才把身份关联到本地账户：

- ID 令牌中的 `email_verified` 为布尔值 `true`（文本 `"true"` 不算），
- 恰好只有一个本地用户拥有该邮箱地址（忽略大小写），
- 该用户自己的邮箱地址在 Specivo 中已标记为已验证，
- 该用户不是管理员、服务账户或匿名用户，
- 该用户在此提供商尚无已关联账户。

其他任何情况都转入 [谁会获得账户](#who-gets-an-account) 中的步骤。

!!! danger "为什么自动关联默认关闭"
    按邮箱匹配正是账户被接管的途径。如果 IdP 允许用户设置未验证的邮箱，或者允许其他租户的用户冒用你的邮箱，那么谁在个人资料里填上 `alice@example.com`，谁就能以 Alice 的身份登录。只有对你自己运维、且在发送 `email_verified: true` 之前确实验证过邮箱的 IdP，才开启此选项。管理员永远不会被自动关联，所以配置有误的 IdP 也无法劫持管理员账户。**对 Microsoft Entra ID 绝不要开启自动关联或“确实会验证邮箱地址”**：它的 `email` 声明未经验证，而且用户可以自行修改。

### 每次登录时跟随 IdP 更新的内容 {#what-follows-the-idp-on-every-sign-in}

用户再次登录时，Specivo 会更新：

- **显示名称**，
- **语言**，取自语言声明，
- **邮箱地址**，**仅当**提供商受信任（**此提供商确实会验证邮箱地址**）、令牌中 `email_verified: true`，且地址来自标准的 `email` 声明时才更新。如果新地址已被其他账户使用，则跳过。没有这层信任，用户的 Specivo 邮箱不会跟随 IdP，否则任何能在 IdP 处编辑自己邮箱的人都能借此改掉这里的邮箱。
- **管理员标志**和**组成员资格**，如果你开启了组同步。

用户从个人资料页关联账户时，不会更新任何内容。

### 限制登录人员 {#limiting-who-can-sign-in}

在账户被创建、关联或登录之前会先执行两项检查，所以被拒绝的用户永远不会被开通账户。

**允许的邮箱域名**。每行一个域名，精确匹配，忽略大小写。子域名不匹配其父域名。域名来源：

- Google 的 `hd`（hosted domain）声明，仅当颁发者恰好是 `https://accounts.google.com` 时。Google 根据 Workspace 成员身份设置它。来自其他任何 IdP 的同名声明会被忽略。
- 否则取邮箱地址，且**仅当提供商受信任**（**此提供商确实会验证邮箱地址**）、令牌中 `email_verified: true`，并且 **邮箱声明** 是标准的 `email` 时。在用户能自行编辑邮箱的地方，未验证的地址什么也证明不了，所以未验证的地址会被拒绝。

未通过检查的用户会收到 `sso_domain_not_allowed`。这意味着对于邮箱未经验证的 IdP（例如 Entra ID），这个列表起不了什么作用。那种情况请改用必需的组。

**必需的组**。见下文。

## 组与角色 {#groups-and-roles}

Specivo 可以从 ID 令牌读取组或角色声明，有三种用法。所有匹配都是精确且区分大小写的：`Specivo-Admins` 和 `specivo-admins` 是两个不同的组。

把 **组声明** 设为声明名称或指向它的点分路径。值必须是字符串列表或单个字符串，其他类型都视为缺失。

| 设置 | 效果 |
|---|---|
| **必需的组** | 只有至少属于其中一个组的用户才能登录。留空则放行该提供商的所有用户。不属于任何一个组的用户会收到 `sso_not_in_required_group`。令牌中完全没有组声明时视为没有任何组，同样会被拒绝。 |
| **管理员组** 配合 **每次登录时根据管理员组设置管理员标志** | 属于这些组的用户在 Specivo 中是管理员。不属于的用户会在下次登录时失去管理员标志。如果降级会导致没有其他能登录的活跃管理员，则不会降级，而是跳过并记录一条警告。 |
| **组映射** 配合 **每次登录时按下方映射更新 Specivo 组成员资格** | 每一行把一个 IdP 组映射到一个 Specivo [用户组](../../projects/index.md)。IdP 组中的用户会被加入对应的 Specivo 组，离开时则被移除。项目角色来自 Specivo 组自身的项目成员资格，所以一条映射就能在多个项目中授予角色。 |

保存提供商后即可添加组映射。请先在 **管理 → 用户组** 中创建 Specivo 组。

同步只会触碰它自己创建的内容。管理员手动添加的成员资格，或由另一个提供商管理的成员资格，永远不会被移除。

!!! note "缺少声明永远不会移除任何人"
    如果令牌中缺少组声明（IdP 的映射器出问题时会这样），Specivo 不会改动任何成员资格，也不会改动任何管理员标志。只有当声明存在且不再包含该组时，才会移除成员资格。如果设置了 **必需的组**，缺少声明仍然会拒绝登录。

!!! warning "Microsoft Entra ID 发送的组过多"
    当用户所属的组多到令牌放不下时，Entra ID 会发送一个标记来代替列表（即“group overage”）。Specivo 无法读到真实列表。如果由必需的组或管理员组决定访问权限，它会拒绝登录并返回 `sso_groups_overage`；否则让用户登录，但不改动任何成员资格。解决办法在 IdP 一侧：见 [Microsoft Entra ID](entra-id.md#group-overage)。

## 会话与注销 {#sessions-and-logout}

**会话时长**。通过提供商登录的会话最长持续 **最长会话时长**（默认 24 小时，上限 168 小时即一周），即使用户一直在使用 Specivo 也是如此。超时后用户需要再次经过 IdP。[会话检查](#the-session-check) 正常工作时，在 IdP 处被禁用的用户会更快被挡住；没有它，这个数字就是用户还能在 Specivo 中继续工作的时间，除非后端通道注销先结束了会话。

**会话跟随其提供商和身份**。每当访问令牌过期（默认每 15 分钟），浏览器会在后台续期会话。一旦提供商被禁用或身份被断开关联，SSO 会话就不再续期并随之结束。关闭提供商会一次性结束来自它的所有会话（管理页面会显示数量；API 在 `PATCH` 响应的 `X-Revoked-Sessions` 头中返回数量）。重新开启也不会恢复这些会话：用户需要重新登录。密码会话和来自其他提供商的会话不受影响。

### 会话检查 {#the-session-check}

Specivo 签发自己的会话令牌。如果没有外力介入，它在会话达到最长时长之前都不会再去询问 IdP。开启 **续期会话时向提供商核查会话**（默认）后，它会加密保存 IdP 在登录时签发的刷新令牌，并在每次续期会话时出示给 IdP，频率最多每 `SSO_IDP_RECHECK_MINUTES` 一次（默认为访问令牌的有效期，15 分钟）：

- IdP 接受：会话续期（如果 IdP 轮换了刷新令牌，则保存新的）；
- IdP 拒绝该用户（`invalid_grant`、`access_denied` 或其他针对用户的拒绝）：用户在那里被禁用、删除或已退出，或者其 IdP 会话已过期。Specivo 会话立即结束，用户下次打开的页面就是登录页面。安全审计日志记录 `sso_session_rejected`；
- 无法连接 IdP，或者 IdP 拒绝的是 Specivo 本身而不是用户（`invalid_client`、`unauthorized_client`、`invalid_scope`、`invalid_request`、`unsupported_grant_type`、`server_error`、`temporarily_unavailable`）：由 **无法连接提供商时** 决定，日志中会有一行 `sso.session.idp_check_failed`。

这适用于任何签发刷新令牌的 OpenID Connect IdP，不需要后端通道注销。API 密钥不受它影响。

**无法工作的情况**。有些 IdP 只有在 Specivo 请求 `offline_access` 作用域时才签发刷新令牌（authentik、Microsoft Entra ID、Okta 等）；对这些 IdP，把它加到 **作用域** 中。Keycloak 对 `openid` 就会签发刷新令牌，而且在 Keycloak 中 `offline_access` 会创建比 Keycloak 退出登录更长寿的离线会话，所以不要给 Keycloak 加它。Specivo 会在每次登录后立即尝试一次刷新令牌。如果 IdP 没有发送，或者拒绝了它（客户端可能没有被允许使用刷新令牌授权），该用户的会话就照旧续期，测试连接会显示原因。检查无法工作不会导致任何人被退出登录。

**IdP 自身的会话超时现在也会生效**。刷新令牌通常只在用户在 IdP 处的会话存续期间有效。当该会话在 IdP 处空闲超时或达到最长时长（Keycloak 中为 **SSO Session Idle**，默认 30 分钟，以及 **SSO Session Max**，10 小时），下一次 Specivo 续期就会被拒绝，用户需要重新登录。如果这太频繁，请在 IdP 处调高这些超时，或者为该提供商关闭检查。

**令牌属于签发它的 IdP**。保存的刷新令牌只会发送给它所来自的颁发者、令牌端点和客户端 ID。更改提供商的颁发者、发现 URL 或客户端 ID 会丢弃其打开会话中保存的令牌，IdP 发现文档中出现新的令牌端点也一样。这些会话之后会在不做检查的情况下续期，直到用户重新登录。

**退出 Specivo**。页头的 **退出登录** 按钮是一个向 `/logout/` 发送 POST 的表单。指向 `/logout/` 的普通链接或书签只会打开“退出登录？”确认页面，不会让任何人退出。如果会话来自某个 SSO 提供商、**退出 Specivo 时也在提供商处退出** 已开启，且 IdP 有结束会话端点，浏览器会被送到 IdP 去结束那边的会话，然后返回 `{APP_URL}/login/?logged_out=1`。这个地址是固定的，请把它在 IdP 处注册为允许的注销后重定向地址。如果 IdP 宕机或该设置关闭，用户就只是从 Specivo 退出。

**后端通道注销** 默认关闭。开启后，IdP 可以直接（服务器到服务器）告知 Specivo 某个用户的会话已结束，Specivo 随即结束匹配的会话。在 IdP 处注册 **后端通道注销 URI**，勾选 **接受来自提供商的后端通道注销**，并确保 IdP 能通过该地址访问到 Specivo。Microsoft Entra ID 不支持它。测试连接会显示 IdP 是否宣告支持。

无论是否有会话匹配，Specivo 对有效的注销请求都回复 200。令牌缺失、无效或被重放时回复 400；提供商未知、已禁用或关闭了后端通道注销时回复 404；当前无法校验令牌时回复 503，以便 IdP 重试：Redis 或 IdP 的密钥无法访问，或者令牌用的是 Specivo 没见过的密钥签名、而它在不到一分钟前刚重新读取过 IdP 的密钥（恰逢密钥轮换之后）。对同一提供商、来自同一发送方地址（IPv6 按一个 /64 网段计）每分钟超过 60 个请求时回复 429。

### 后端通道注销会结束什么 {#what-a-back-channel-logout-ends}

由 **提供商结束会话时** 决定：

| 选项 | 结束的内容 |
|---|---|
| 结束匹配的 Specivo 会话（默认） | 注销请求所指 IdP 会话（其 `sid`）对应的 Specivo 会话。只指明用户（`sub`）的注销会结束该用户来自此提供商的所有会话。 |
| 结束该用户来自此提供商的所有会话 | 来自该身份的所有会话，不论属于哪个 IdP 会话。 |
| 结束该用户的全部会话并关闭其 API 密钥 | 同上；此外，如果该账户只通过 SSO 登录（没有密码），则它的所有会话（包括来自其他提供商的）以及全部 API 密钥（含 MCP 密钥）都会被关闭。安全审计日志记录 `user_deprovisioned`，原因为 `sso_backchannel`。 |

最后一个选项永远不会停用账户，也不会触碰有密码的账户或服务账户（这两类按第二种行为处理）。如果用户之后再通过 IdP 登录，是可以的，但其 API 密钥保持关闭，直到本人或管理员重新开启。IdP 对主动退出的用户和被禁用的用户发送的是同一种注销，所以只有当你能接受“在 IdP 处退出也会关闭该用户的 API 密钥”时才选它。对同一会话重复发送注销不会有任何变化。

## 用户离职处理 {#offboarding-people}

Specivo 没有 SCIM，所以它只能通过以下途径得知有人离开。IdP 支持哪些就尽量都用上。各提供商页面各有一份简短的操作手册：[Keycloak](keycloak.md#offboarding)、[authentik](authentik.md#offboarding)。

1. **在 IdP 处禁用该用户**。他们无法再登录。[会话检查](#the-session-check) 正常工作时，其 Specivo 会话会在下次续期时结束，通常在一个访问令牌有效期（15 分钟）内，最多不超过 `SSO_IDP_RECHECK_MINUTES` 加上该有效期。没有会话检查时，会话会一直有效，直到你手动结束或达到最长会话时长（最多一周）。
2. **后端通道注销**（IdP 支持的话）会在 IdP 结束其会话的同时立即结束 Specivo 会话。哪些 IdP 操作会触发注销各有不同：Keycloak 在管理员将用户登出时发送（禁用时不发送），authentik 在用户被禁用、删除或退出时发送。选择 **结束该用户的全部会话并关闭其 API 密钥** 时，还会一并关闭其 API 密钥（见 [后端通道注销会结束什么](#what-a-back-channel-logout-ends)）。
3. **登录被拒绝**：因为失去了必需的组、邮箱域名不再符合要求，或 group overage 隐藏了其所属组（`sso_groups_overage`），会结束来自该身份的剩余会话。
4. **在 Specivo 中停用该用户**。在 **管理 → 用户** 中打开该用户的页面，点击 **停用账户**（或调用 `POST /api/v1/admin/users/{id}/deactivate/`）。这对所有账户都有效，无论是否使用 SSO，包括服务账户。它一步完成：结束所有会话（浏览器的下一次请求会被拒绝）并关闭其全部 API 密钥。密钥会保留但处于关闭状态，所以历史记录仍可查阅。**重新启用账户** 让用户可以再次登录，但 API 密钥仍然关闭：用户可在自己的 API 密钥页面重新开启，或由本人或管理员创建新密钥。你不能停用自己的账户，也不能停用最后一个活跃的管理员。
5. **断开其身份的关联**（在用户的管理页面操作），以结束来自该身份的会话。

每个提供商还有一个选项 **当登录被必需的组或允许的邮箱域名拒绝时停用 Specivo 账户**（`deactivate_on_access_loss`，默认关闭）。开启后，被拒绝的登录（第 3 步，包括 group overage）会像第 4 步那样停用账户，但仅针对已经关联到该身份的账户。Specivo 绝不会以这种方式停用服务账户，也不会停用最后一个活跃的管理员（而是记录一条警告）。

**API 密钥**。通过 SSO 登录的用户可以创建 API 密钥（默认允许）。密钥不经过 IdP，所以会话检查和普通的后端通道注销都拦不住它：在 IdP 禁用该用户之后，密钥会继续有效，直到密钥过期、你停用该用户，或者一次带 **结束该用户的全部会话并关闭其 API 密钥** 的后端通道注销把它关闭。这是为 SSO 用户保留密钥的取舍：IdP 故障或忘了加某个组时，智能体和脚本仍能继续工作，但离职处理就需要上述步骤之一。如果不想这样，在 **管理 → 设置 → 身份验证** 中关闭 **通过 SSO 登录的用户可以使用 API 密钥**。它作用于没有密码且有已关联身份的账户：这些账户不能创建密钥，设置关闭期间其现有密钥也会被拒绝。无论该设置如何，这类账户都不能通过 **忘记密码** 获得密码；管理员仍可主动为其设置一个。有密码的用户和服务账户不受影响。

管理员的 API 密钥可以通过管理 API（`/api/v1/admin/sso/...`）读取单点登录配置，但不能修改。创建、编辑或删除提供商及其组映射，以及保存身份验证设置，都需要管理员登录 Specivo 操作；API 密钥会收到 403 `api_key_not_allowed`。因此泄露的密钥无法添加一个把自己的用户映射为管理员的身份提供商。所有会授予登录途径的管理操作（例如重置密码）同样如此；见 [管理员密钥不能做什么](../../ai-agents/api-keys.md#what-an-administrators-key-cannot-do)。

## 身份验证设置 {#authentication-settings}

**管理 → 设置 → 身份验证** 作用于整个实例：

| 设置 | 作用 |
|---|---|
| 在登录页面隐藏密码表单 | 用一个指向 `/login/?local=1` 的链接 **使用本地账户登录** 代替表单。没有任何已启用的提供商时，表单始终显示。 |
| 仅管理员可使用密码登录 | 其他人都必须使用 SSO。上面的链接仍会显示表单，但非管理员的密码登录会被拒绝。此时所有被拒绝的密码登录都收到同样的“登录名或密码不正确”回应，被锁定、已停用或未验证的管理员账户也一样，所以表单不会泄露谁是管理员。原因记录在 `specivo.sso` 日志中（`sso.local_login.refused_admin`）。输错密码仍会让管理员被锁定一段时间；期间他们仍可通过 SSO 登录。 |
| 通过 SSO 登录的用户可以使用 API 密钥 | 默认开启。 |
| 将登录页面重定向到 | 把访客直接送到某一个提供商。`/login/?local=1` 会绕过它，已登录的访客、退出登录、重置密码和任何 SSO 错误也会绕过，所以出故障的提供商不会造成循环。 |

如果你把自己锁在了这些设置之外，见 [重新进入](../configuration.md#single-sign-on-getting-back-in)。

## 环境中的设置 {#settings-in-the-environment}

这些设置像其他 [配置](../configuration.md) 一样写在 `.env` 中，作用于所有提供商。

| 变量 | 默认值 | 用途 |
|---|---|---|
| `APP_URL` | `http://localhost:8030` | Specivo 的公开地址。重定向和注销地址都由它构造。配置提供商之前先设置它。 |
| `SSO_FORCE_LOCAL_LOGIN` | `false` | 应急开关：始终显示密码表单，从不重定向，忽略隐藏表单和仅管理员的设置。 |
| `SSO_ALLOW_INSECURE_HTTP` | `false` | 允许 `http://` 的 IdP 地址。仅用于一次性的测试 IdP。绝不要在正式 IdP 上使用：令牌和密钥会以明文传输。 |
| `SSO_HTTP_TIMEOUT_SECONDS` | `5` | 每次向 IdP 请求的最长等待时间。 |
| `SSO_IDP_RECHECK_MINUTES` | 访问令牌有效期（15） | 每个会话续期时向 IdP 询问的最高频率。见 [会话检查](#the-session-check)。`0` 表示每次续期都询问。 |
| `SSO_CLOCK_SKEW_SECONDS` | `60` | 校验令牌时间时，Specivo 与 IdP 的时钟允许相差多少。大于 300 的值会被降为 300。与其调高它，不如校准时钟（使用 NTP）。 |
| `SPECIVO_SSO_SECRET_<NAME>` | 无 | 让提供商指向的客户端密钥。 |

## 升级到带 SSO 的版本 {#upgrading-to-a-release-with-sso}

- **设置 `APP_URL`**，再配置第一个提供商。
- **`/logout/` 现在需要 POST**。页头的链接现在是按钮。指向 `/logout/` 的书签会显示确认页面。
- **`SECRET_KEY`**：如果之后轮换了它，要重新输入已存储的客户端密钥（见 [客户端密钥](#the-client-secret)）。
- **现有会话** 继续有效。
- **会话检查** 在升级后对所有提供商开启，包括已有的。它不会让任何人被退出登录：升级时已打开的会话不带 IdP 刷新令牌，照旧续期；之后开始的会话在 IdP 签发刷新令牌时会被检查（IdP 需要时把 `offline_access` 加到 **作用域**）。首次登录之后点击 **测试连接**，查看它是否正常工作。

## 故障排查 {#troubleshooting}

登录失败时，用户会回到登录页面并看到一条消息。如果是在自己的账户页面操作（**关联** 失败），则回到 **个人资料** 页。消息从不复述 IdP 说了什么，所以请结合错误代码和日志。代码出现在地址中，形式为 `?sso_error=<code>`。原因在 Specivo 日志中。`api` 容器每行写一个 JSON 对象（`DEBUG=true` 时为纯文本）。SSO 相关的日志行来自记录器 `specivo.sso`，消息以事件名开头，例如 `sso.id_token.rejected ... reason=wrong_issuer` 或 `sso.login.refused_policy`。查看方式：`docker compose logs api | grep specivo.sso`。日志中永远不含令牌或密钥。

| 代码 | 用户看到的内容 | 检查什么 |
|---|---|---|
| `sso_state_invalid` | “你的登录已过期，或是在另一个浏览器中发起的。” | 登录耗时超过 10 分钟、用户点了后退按钮、在另一个浏览器或标签页组中打开了链接，或者屏蔽了 Cookie。该 Cookie 的作用范围是 `/auth/oidc/`。在代理后面时，确认代理没有剥离 Cookie。重试即可。 |
| `sso_idp_error` | “身份提供商拒绝了登录。” | IdP 返回了错误，例如因用户未被分配到该应用而返回 `access_denied`，或者拒绝了授权码。令牌请求失败也显示同样的消息。检查客户端密钥、重定向 URI 以及用户在 IdP 处的访问权限。日志中有 IdP 的错误代码。 |
| `sso_idp_unreachable` | “身份提供商不可用。” | Specivo 在 `SSO_HTTP_TIMEOUT_SECONDS` 内无法访问 IdP 的发现文档、密钥或令牌端点，或者收到了服务器错误。当令牌指向一个 Specivo 不认识的签名密钥、而它刚刚重新读取过 IdP 的密钥时（IdP 可能轮换了密钥），也会显示一分钟；一分钟后重试即可。从 Specivo 容器内检查 DNS、防火墙和证书。期间管理员可以使用 **使用本地账户登录** 链接。 |
| `sso_discovery_invalid` | “单点登录配置不正确。” | 发现文档或密钥不可用：文档中的颁发者不是你输入的那个、某个端点是 `http://`，或者没有可用的签名密钥。点击 **测试连接**。 |
| `sso_provider_misconfigured` | “单点登录配置不正确。” | 客户端密钥无法读取或缺失。重新输入，或检查环境变量名以及该变量是否已在容器中设置。 |
| `sso_token_invalid` | “单点登录失败。请重试。” | ID 令牌未通过校验。原因见日志：颁发者或受众不对（颁发者或客户端 ID 不匹配）、签名错误、令牌已过期（服务器之间时钟偏差）、缺少 `nonce` 或 `sub`、令牌用了 Specivo 不接受的算法签名（例如 `HS256`），或者发送了 `max_age` 却缺少 `auth_time` 或它太旧（**关联** 操作始终如此：IdP 没有让用户重新登录）。 |
| `sso_unavailable` | “单点登录暂时不可用。” | Specivo 无法连接 Redis，而它需要 Redis 来保存登录状态。本地登录仍然可用。检查 `redis` 容器。 |
| `sso_account_not_provisioned` | “这里没有账户与你的身份提供商账户关联。” | 没有已关联的账户，自动关联不适用，且即时创建已关闭。开启 **首次登录时创建账户**，让用户从个人资料页关联账户，或检查 [关联条件](#linking-an-existing-account)。 |
| `sso_account_disabled` | “此账户已被禁用。” | 关联的用户已停用、被管理员锁定、尚未验证邮箱地址，或是服务账户。检查 **管理 → 用户**。 |
| `sso_email_missing` | “身份提供商没有发送邮箱地址。” | 即时创建需要邮箱。在 IdP 处添加 `email` 作用域和声明，或把 **邮箱声明** 设为正确的名称。Entra ID 需要添加 `email` 可选声明。 |
| `sso_email_conflict` | “使用此邮箱地址的账户已存在。” | 即时创建会产生第二个使用已存在邮箱的账户。用户应改用密码登录，再从个人资料页关联账户。 |
| `sso_identity_in_use` | “此身份提供商账户已关联到另一个账户。” | 关联时出现。该 IdP 身份属于另一个 Specivo 用户。先在那边断开关联。 |
| `sso_provider_already_linked` | “你的个人资料已关联了此身份提供商的一个账户。” | 关联时出现。该用户在此提供商已有关联账户。 |
| `sso_domain_not_allowed` | “你的邮箱域名不允许在此登录。” | 邮箱域名不在列表中，或邮箱未经验证，或提供商没有被设为信任邮箱验证，或 IdP 没有发送邮箱。见 [限制登录人员](#limiting-who-can-sign-in)。 |
| `sso_not_in_required_group` | “你的身份提供商账户不属于任何允许在此登录的组。” | 用户不属于任何必需的组，或令牌没有组声明。检查 **组声明** 路径、IdP 的组映射器、作用域，以及组名是否完全一致（包括大小写）。 |
| `sso_groups_overage` | “你的身份提供商发送的组太多，无法读取。” | Entra ID 的 group overage。见 [Microsoft Entra ID](entra-id.md#group-overage)。 |
| `sso_last_sign_in_method` | “这是你唯一的登录方式。” | 断开关联时出现。用户没有密码，也没有其他已关联账户。先设置密码或关联另一个账户。 |
| `sso_access_denied` | “单点登录失败。请重试。” | 上述三个策略代码的通用形式。你应该看到的是具体代码之一。 |
| `sso_token_exchange_failed` | 显示为 `sso_idp_error`。 | IdP 的令牌端点拒绝了授权码。检查 IdP 处的客户端密钥、重定向 URI 和 PKCE 设置。 |

管理员常遇到的其他情况：

- **IdP 提示“invalid redirect URI”**。它必须与 **连接** 卡片上的地址逐字符一致，包括协议（`https`）、主机、端口和末尾斜杠。检查 `APP_URL`。
- **提供商列表显示“无法读取，请重新输入”**。`SECRET_KEY` 变了。重新输入密钥。
- **用户点击提供商按钮后看到 404 页面**。该提供商已禁用，或者其标识串已更改而旧链接被缓存了。
- **用户的显示名称或语言变了，但邮箱没变**。除非提供商被信任用于邮箱验证，否则这是正常的。
- **用户在 24 小时后被退出 Specivo**。这是 **最长会话时长** 的作用。
- **用户在中断半小时左右后被退出**。其在 IdP 处的会话空闲超时，会话检查在下次续期时发现了这一点。调高 IdP 的空闲超时，或为该提供商关闭会话检查。见 [会话检查](#the-session-check)。
- **测试连接说提供商拒绝了刷新令牌**。客户端可能未被允许在 IdP 处使用刷新令牌授权。允许它（authentik：**Grant Types → Refresh token**）。
