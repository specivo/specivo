# 子工作项与层级 {#subtasks-hierarchy}

大块的工作很少能塞进一个工作项（Issue）里。在 Specivo 中，拆分的办法是给工作项指定一个 **父工作项**，它就成了 **子工作项**。父工作项统揽全局，子工作项则是它下面一件件具体的事。

## 把工作项设为子工作项 {#make-an-issue-a-subtask}

在子工作项上把 **父工作项** 字段指向对应的父工作项即可。[创建](creating.md)工作项时可以设置，之后[编辑](updating.md)时也可以。如果一个父工作项要带多个子工作项，先创建父工作项，再把各个子工作项逐一指向它。父工作项必须与子工作项属于同一项目，并且你有权查看。

## 搭建层级结构 {#build-a-hierarchy}

子工作项还可以有自己的子工作项，因此可以按实际结构来组织工作：一个史诗下面有若干功能，每个功能下面又有若干任务。Specivo 支持 **最多 10 层** 嵌套，远超大多数团队的实际需要。给一个带有子工作项的工作项更换父工作项时，它的子工作项会跟着一起移动，所以其中层级最深的那个也必须落在限制之内；否则这次修改会被拒绝，所有工作项都保持原位。

```
ACME-1  Checkout redesign            (parent)
├─ ACME-2  Cart page
│  ├─ ACME-5  Update line-item layout
│  └─ ACME-6  Wire up quantity stepper
└─ ACME-3  Payment step
   └─ ACME-7  Add saved-card selector
```

## 子工作项如何汇总 {#how-subtasks-roll-up}

打开父工作项，它的子工作项就列在下方。这样在一个页面里就能看到它下面的全部工作，以及每一部分的进展。用父工作项跟踪整体进度，用子工作项来指派和处理具体的部分。

!!! tip "子工作项与关联的区别"
    如果一个工作项确实是另一个更大工作项的*组成部分*，使用 **父子** 关系。如果两个工作项地位平等，只是互相依赖或互相引用，使用[关联](relations.md)（阻塞、关联到、重复于）。

!!! note "跨项目移动前先脱离层级"
    只有 **独立** 的工作项才能[移动到其他项目](updating.md#move-an-issue-to-another-project)。有父工作项或自身带有子工作项的工作项，必须先从层级结构中脱离出来，这样父工作项和它的子工作项就不会分散在不同项目里。

!!! note "删除父工作项"
    仍有子工作项的工作项无法删除，这样子工作项就不会被误删。先删除这些子工作项，或者给它们另外指定父工作项。如果批量删除时同时选中了父工作项及其全部子工作项，Specivo 会一次性全部删除。
