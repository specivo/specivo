# 子工作项与层级结构 {#subtasks-hierarchy}

大块的工作很少能装进一个工作项（Issue）里。在 Specivo 中，你可以给一个工作项指定 **父工作项**，它就成为一个 **子工作项**。父工作项是总纲，子工作项是它下面一个个具体的任务。

## 把工作项变成子工作项 {#make-an-issue-a-subtask}

在子工作项上设置 **父工作项** 字段，让它指向父工作项。可以在[创建](creating.md)工作项时设置，也可以之后[编辑](updating.md)时再设置。要让一个父工作项带多个子工作项，先创建父工作项，再把每个子工作项指向它。

## 构建层级结构 {#build-a-hierarchy}

子工作项还可以有自己的子工作项，因此你可以按真实的工作结构建模：一个史诗下面是若干功能，每个功能下面是若干任务。Specivo 支持 **最多 10 层** 嵌套，远超绝大多数团队的实际需要。给一个已有子工作项的工作项指定新的父工作项时，它的子工作项会一起移动，所以最深的那一层也必须在 10 层限制之内；否则这次修改会被拒绝，所有工作项都保持原位。

```
ACME-1  Checkout redesign            (parent)
├─ ACME-2  Cart page
│  ├─ ACME-5  Update line-item layout
│  └─ ACME-6  Wire up quantity stepper
└─ ACME-3  Payment step
   └─ ACME-7  Add saved-card selector
```

## 子工作项如何汇总 {#how-subtasks-roll-up}

打开父工作项，它的子工作项会列在下方，因此父工作项提供了一个统一视图，能看到它下面的全部工作以及每一项的进展。用父工作项追踪整体进度，用子工作项指派和处理具体任务。

!!! tip "子工作项与关联的区别"
    当一个工作项确实是另一个更大工作项的 *一部分* 时，使用 **父子** 关系。当两个工作项是平级的，只是相互依赖或相互引用时，使用[关联](relations.md)（阻塞、关联到、重复于）。

!!! note "跨项目移动前先脱离层级"
    只有 **独立** 的工作项才能[移动到其他项目](updating.md#move-an-issue-to-another-project)。有父工作项或自身带有子工作项的工作项，必须先脱离层级结构，这样父工作项和它的子工作项就不会被拆散到不同项目里。
